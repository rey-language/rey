# Owned raw byte buffer, revision 1

This runtime sector consumes the trusted raw-memory primitives. It is an
internal byte-storage building block for strings, numeric buffers and compiler
work space. It is not a managed Vec, root stack, collector, inferred region or
promotion implementation. Its source belongs under `runtime-rey/buffer/` and
is compiled as an explicitly authorized runtime source unit.

The combined gate passes 261 checks and 47 executions on each ARM64 OS,
including nine buffer fixtures. Evidence is in the parallel ledger. Capacity
and byte-copy records are expected values checked by the fixtures; no RSS or
language-wide speedup is established.

## API and ownership

All sizes and lengths are byte counts. `__rey_raw_address` below is the
internal source type; ordinary packages cannot call this raw API.

```text
pub func rawBufferCreate(capacity: int): __rey_raw_address
pub func rawBufferLength(handle: __rey_raw_address): int
pub func rawBufferCapacity(handle: __rey_raw_address): int
pub func rawBufferData(handle: __rey_raw_address): __rey_raw_address
pub func rawBufferSetLength(handle: __rey_raw_address, length: int): void
pub func rawBufferGrow(handle: __rey_raw_address, minimumCapacity: int): void
pub func rawBufferRelease(handle: __rey_raw_address): void
```

The stable handle owns one 64-byte metadata mapping and, when capacity is
positive, one data mapping of exactly the requested capacity. Capacity zero
has a null data address and length zero. Creation accepts nonnegative capacity;
length starts at zero and newly mapped data bytes are zero. SetLength accepts
only `[0, capacity]`; it does not resize or promise that previously used bytes
become zero when length grows again.

Grow accepts a nonnegative minimum. It does nothing when capacity suffices;
otherwise use at least eight bytes and geometric growth, choosing the required
minimum when doubling would overflow signed i64. Map new non-executable data,
copy exactly the live `[0, length)` bytes, update the handle and release the
previous positive-capacity mapping exactly once. Newly mapped spare bytes
remain zero. The handle stays stable; every previously borrowed data address
is invalid after an actual growth and must be reacquired.

Release consumes a live handle: read its metadata, clear its magic, unmap its
data if present, then unmap the metadata using the original sizes. Use after
release and repeated release are trusted caller bugs; reading unmapped metadata
cannot safely diagnose them. No reference counting, implicit collection or
automatic ownership inference is claimed.

## Metadata layout

| Offset | Representation | Meaning |
| --- | --- | --- |
| 0 | i64 | magic, decimal 1380276546 |
| 8 | i64 | initialized byte length |
| 16 | i64 | data capacity in bytes |
| 24 | raw address slot | owned data mapping base, or null |
| 32..63 | zero bytes | reserved |

Check the magic and metadata invariants on API entry before deriving data
addresses. Use typed address loads/stores at offset 24. A raw byte-copy routine
must not copy pointer-bearing metadata, root arrays or managed reference
buffers: those require layouts and typed address/reference copies. The raw
buffer itself holds bytes only and supplies no tracing policy for a future Vec.

Validation uses `__reyRawFail(code)`: code 1 for invalid sizes, 2 for metadata
invariants, and 3 for invalid lengths. It always exits with runtime-error status
1; evaluator diagnostics retain the code and source. Native code-specific
messages await the runtime I/O layer.

## Gate

Implement the entire module and fixtures before first testing. The source
pipeline must check/lower/verify/evaluate the actual runtime module, emit and
execute it on Darwin arm64 and Linux arm64, and verify both image formats.
Exercise capacity zero, unchanged and geometric growth, live-byte preservation
including embedded NUL and all byte values, zero spare storage after growth,
shrink/set-length/regrow behavior, separate handles, and repeated create/grow/
release. Reject negative sizes and lengths beyond capacity before memory access.
Record requested capacities and copied byte counts in fixtures; neither equals
RSS, allocator latency or a language-wide memory/performance result.
