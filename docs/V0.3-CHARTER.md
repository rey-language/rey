## 3. Locked defaults (charter-level, vetoable only by owner)

- Declaration return types stay `: T`; `->` only inside type expressions.
- Conditions must be `bool` (no truthiness).
- `int / int` → `int` truncating; any `float` operand → `float`. `%` likewise int-preserving.
- `string[i]` → `char`. Strings are byte-indexed, **ASCII semantics documented**; Unicode = v0.4.
- `match` is a statement in v0.3; arms may be blocks; `_` wildcard; exhaustiveness enforced.
- Statement terminator `;` required. Comments `//` and `/* */` (non-nested).
- Numeric separators `_` allowed in literals. No literal suffixes. Hex/binary ok.
- String escapes: `\n \t \r \\ \" \' \0 \xNN`. Interpolation `{expr}`; literal-brace escaping defined in SPEC.
- Diagnostics: `file:line:col: error: message`; no ANSI required. `check` silent on success.
- Exit codes: `0` ok; `1` any error (compile/check/runtime); `2` usage/unsupported.
- Compiler must use real clang (`/usr/bin/clang`); the PATH `clang` shim is broken.
- Build artifacts live in `build/` (gitignored); committed binaries leave the source tree at ship.
- File I/O builtins (`readFile`, etc.) and current std-facing builtins stay per SPEC's builtins appendix.
- `create` rule, method list, CLI, and diagnostics format are frozen interfaces (below).

## 5. Frozen interfaces

### 5.1 CLI contract

```
rey build <file>    → native binary emits executable, prints resulting path; interpreter: exit 2 "interpreter cannot emit native binaries; use rey"
rey run <file>      → compile/interpret then execute; runtime errors exit 1 with diagnostics
rey check <file>    → typecheck only; silent+exit 0 on success; diagnostics+exit 1 on failure
rey --version       → "<name> 0.3.0"
rey --help
```

### 5.2 Diagnostics format

`<file>:<line>:<col>: error: <message>` (also `warning:` / `note:`). One per line. No ANSI.

### 5.3 Conformance fixture format

```
tests/conformance/<area>/<case>/
  main.rey               required — the program
  expected.stdout        required — exact stdout bytes (may be empty file)
  expected.exit          optional — integer, default 0
  expect_check_fail      optional — if present, `check` MUST fail; file content = substring expected in diagnostics
```

Areas: `types/ exprs/ control/ data/ funcs/ modules/ errors/ robustness/` (plus `_smoke/`).
Runners: `scripts/conformance.sh --engine <cmd>`; differential compares engines.

## 7. Verified defect ledger (owner must see these all die)

**v1 (Rust oracle):**
- `imports.rs`: duplicate module import in nested modules → `TypeError: 'lexer' is already declared in this scope` running `main.rey` (kills bootstrap path). Duplicate import must be idempotent.
- `interpreter/`: assignment to global from inside a function → `error[runtime]: Undefined variable 'g'` (reads work).
- variadic function re-exported through module: `math.sum(1,2,3,4)` → `Expected 1 arguments but got 4` (direct call fine) — variadic flag lost across module resolution.
- `lexer.rs`: `\x` escapes broken in strings; needs `_` separators; char literals plumbing.
- `parser.rs`: no `++/--` parse (v1-side semantics verify), no range patterns, no `Enum::` in all positions, bare variant in match, `export` handling, both import spellings.
- `typecheck.rs`: capitalized types accepted (must error with fix-it), `.length()`/`upper()` naming, exhaustiveness, unions/nullable narrowing, `instanceof` typing, int division typing, `create` static typing.
- `main.rs`: CLI must match §5.1; `check` must print real diagnostics + exit codes.

**Native compiler (`rey-compiler/`):**
- codegen emits `call i64 @0(...)` for ALL user function calls → clang `use of undefined value '@0'`. Root cause: untyped field-access heuristic feeding call emission (~lines 526, 653–656 of `src/codegen/main.rey`). Fix = typed lowering (checker resolves call targets).
- self-build SIGSEGV (exit 139); `check token.rey` → panic `Vec index out of bounds`; `check enum_match.rey` → hang; `check` prints `Success: a.out` but writes nothing.
- silent wrong-code: lambdas/dicts/tuples compile to literal `0`; `for x in vec` emits nothing; index assignment silently dropped; unknown `instanceof` → constant `true`; `match` not parsed.
- always `-O0`; DEBUG spam in output; tool errors swallowed as `DEBUG clang obj failed: ?`.
- runtime: HashMap delete breaks probing; `toString` >65536 reads `x-16`; escapes.

**Repo/docs:** conflict markers in `syntax.md`/`primer.md`; `spec/` contradicts; batch of committed build artifacts; `.gitignore` gaps; stale `~/.reyc/std` symlink; broken PATH clang shim.

## 10. Decision log

The original 15 decisions above were arbitrated by the owner (Misbah) on 2026-10-16 during
planning, from a full audit of the workspace (8 subagent reports + live reproductions).
Superceded documents: `syntax.md`, `spec/` (kept for archaeology until ship, removed
at ship with owner approval).

- **2026-10-16 — String `+` (owner-arbitrated):** Require explicit conversion. `string + string` concatenates; mixed string/non-string `+` (including `1 + "s"` and `"s" + 1`) is a type error in both engines. Callers must explicitly convert or interpolate. This overrides the v1 baseline implicit concatenation and is a target requirement, not a claim of implementation. The conformance negative-int-plus-string expectation is now owner-confirmed.
- **2026-10-17 — Payload enum forms (owner-arbitrated):** A payload variant may declare positional types (`Count(int)`) or named typed slots (`Count(value: int)`). Constructor arguments and match bindings are positional in declaration order for either form. A variant may not mix named and positional slots. See `SPEC.md` §§3.4, 4.5, 13. This is a target requirement, not an implementation claim.
- **2026-10-17 — Lambda capture snapshot (owner-arbitrated):** Immutable captures snapshot values at lambda creation. Scalars are copied; aggregate/reference values retain their normal shared identity. A captured binding cannot be reassigned by the lambda. See `SPEC.md` §4.3. This is a target requirement, not an implementation claim.
- **2026-10-17 — Signed integer overflow (owner-arbitrated):** Signed 64-bit arithmetic overflow is a runtime error, including increment/decrement, unary negation, and `INT64_MIN / -1`. Division by zero remains a runtime error. Engines must behave identically across build modes and must not rely on wrapping, debug/release differences, or LLVM poison. See `SPEC.md` §6.3. This is a target requirement, not an implementation claim.
- **2026-10-17 — Byte-string model (owner-arbitrated):** Preserve UTF-8 source bytes and raw `\xNN` bytes exactly, without Unicode normalization; strings are byte sequences (including NUL/invalid UTF-8) with byte length/indexing; `char` is exactly one byte. Case conversion is ASCII-only and string operations are not Unicode-aware. This byte model is a v0.3 conformance requirement, not a deferred Unicode feature. Rust `String` limitations are implementation gaps. See `SPEC.md` §§2.3–2.4, 9.1, 11, 12, 13.
- **2026-10-17 — Explicit conversions (owner-arbitrated):** Supported scalar conversions produce scalar results; invalid input and out-of-range conversion are runtime errors with exit status 1. Conversion methods on unsupported source types are rejected statically. See `SPEC.md` §§9.1, 10. This is a target requirement, not an implementation claim.
- **2026-10-17 — Built-in type arguments (owner-arbitrated):** Preserve `Vec`, `HashMap`, `Option`, and `Result` arguments during static checking and erase parameterization only at runtime. Erasing arguments before checking is an implementation bug, not the target behavior. `Vec<T>` uses the logical element rules of `[T]`; HashMap keys remain string-only; bare built-ins default to `any` subject to that key restriction. Nullable, union, function, and tuple types may compose as arguments. This does not add user-defined generics, constraints, generic inference, or monomorphization. See `SPEC.md` §3.1. This is a target requirement, not an implementation claim.
- **2026-10-17 — Landing hold (latest owner instruction):** The one-commit landing goal is not standing authorization. Do not commit, push, tag, or publish until the user explicitly approves landing/publication. This hold applies to local as well as remote actions and supersedes any inference of automatic approval from decision #14 or gate M5.
- **2026-10-17 — Owner tiebreaker (Misbah):** "use whatever makes this language faster, smaller to work with, easier to work with, better to work with and more memory efficient — base any decisions off of those." This is the tiebreaker for open language and implementation decisions: prefer runtime speed, a small implementation surface (fewer special cases, less code in both engines), ergonomics, and low memory. Where the current implementations already agree on a reasonable behavior, document that behavior instead of changing both engines. Frozen charter decisions §2 and §3 still stand. This does not add user generics, mutable captures, bitwise operators, or-patterns, or Unicode-aware strings.
- **2026-10-17 — Imported-module initialization:** Imported modules' top-level statements, including `var` and `const` initializers, execute exactly once, in dependency post-order — each module after all of its imports — before the entry file's top-level statements. Then entry `main()` runs if it is defined. Imported `main` is never auto-called. A module imported along several paths runs once. Import cycles stay compile errors and do not run. See `SPEC.md` §8. Rationale: one-time init needs no lazy guard on later reads (faster), the oracle already runs this order and the native multi-unit milestone needs the same initializers (smallest change), and a module-level `var` then just works. Verified on oracle `rey-v0` `fc8e55851ceda6aac442e1ad90bf598cb1c191a44013e150c751ddeb3a0e1ac8` with `tests/conformance/modules/imported-init-order/`. This is the language rule; native codegen still has to emit the inits.
- **2026-10-17 — One file per module:** A directory module is only `main.rey`. `import math` does not merge sibling `math/*.rey` files and does not fall back to a flat `math.rey`. If the module file exists, a brace group names public declarations of that file only. If it does not exist, each brace name is a child module (`import modules::{account}`, folder before file). `import parent::child` remains a child path whether or not `parent/main.rey` exists. See `SPEC.md` §§1, 7. Rationale: scanning every sibling costs time and memory and is a second meaning of a namespace; the compiler's own imports are symbols from `main.rey`. The missing-file brace form stays because both engines and the folder-priority fixtures already use it.
- **2026-10-17 — Float spelling:** Finite `toString` is Rust 1.98 `f64` Debug (shortest round-trip), dropping a trailing `.0` on a plain integer spelling (`1.0` is `1`, `-0.0` is `-0`). Non-finite values are `inf`, `-inf`, and `NaN`. The largest finite value is `1.7976931348623157e308`, not a 309-digit fixed-point integer. See `SPEC.md` §9.1. Rationale: one formatter, shorter output, less memory. The shared `{:.0}` branch for integral values is the extra special case to remove.
- **2026-10-17 — Char ordering:** Two `char` values compare by unsigned byte value. A `char` is not converted to `int` or `string` for `<`, `<=`, `>`, or `>=`. See `SPEC.md` §§6.3, 11. Rationale: one byte compare, no allocation, and §11 already said chars compare by byte value.
