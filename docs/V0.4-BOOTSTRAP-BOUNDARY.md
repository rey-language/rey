# v0.4 Linux x64 bootstrap boundary

## Pinned seed candidate

The seed identity is pinned by [v04-linux-x64-seed.sha256](v04-linux-x64-seed.sha256).
The expected file is `build/v04/rey`; the binary stays outside Git. The seed
candidate used for the bounded B01 smoke is the saved discovery S1 at
`~/rey/discovery/selfhost/S1`. Discovery also retains S2 and S3 with the same
SHA-256. The smoke runner accepts a seed only when the hash matches and ELF
inspection finds ELF64 AMD x86-64 `ET_EXEC`, with no `PT_INTERP`, `PT_DYNAMIC`,
or dynamic entries.

Recorded provenance:

- **Artifact origin:** `~/rey/discovery/selfhost/S1`, retained from the V0.4
  discovery run.
- **Acquisition:** copied from that retained artifact to the caller supplied
  `--seed` path; the bootstrap runner stages a hash-checked copy into its fresh
  minimal root. No seed binary is committed here.
- **SHA-256:**
  `64c8bbe4e559a2355b79bfa0d357bd6e81d6dee92bbac73fe520165004883ee6`.
- **Build revision:** not recorded in the retained discovery evidence.
- **Build flags:** the saved S1 was produced from H with
  `--target linux-x64 --regions --managed --trust-packed-output
  --selfhost-fast-exit`. The exact invocation and output hashes are in
  `~/rey/discovery/V04-DISCOVERY.md`.
- **Legacy ancestry:** H came from the v0.3.1 seed through the legacy runtime,
  Python embedding and LLVM/Clang route. H is not in the v0.4 Linux native
  producer path.
- **Owner approval:** not recorded. This seed is a pinned candidate for B01
  harness evidence, not an approved release trust root.

The saved stages are byte-identical, but they were produced with fast exit and
trusted packed output. That history does not establish normal teardown. B01
therefore verifies identity and a new normal-mode tiny fixture build; the
full chain remains blocked until its separate memory admission and seed
qualification are complete.

## Producer boundary

`scripts/v04-selfhost-linux-x64.sh --candidate` stages the exact Git revision
using `git archive`, copies the pinned seed, and performs one build to
`WORK/S1`. The source tree is read-only inside the producer service. The seed,
compiler sources and requested input are placed in a minimal chroot containing
no shell, C runtime, dynamic loader, libraries, Python, compiler, linker or
network tools. The outer host service keeps `strace` outside the chroot and
records every `execve` and `execveat`. Its allowlist names the chroot entry and
the expected initial Rey binary path; any further or failed exec attempt is
rejected. The producer receives an empty `PATH`.

The service uses cgroup v2 `MemoryMax` and `MemorySwapMax`, and a seccomp
address-family filter that permits only Unix sockets. The runner verifies the
effective cgroup values and active seccomp mode from inside that service. A
network probe confirms that IPv4/IPv6 socket creation fails with `EPERM`.
`ProtectSystem=strict`, read-only source and seed paths, and a writable output
directory bound the host service; chroot prevents the Rey producer from seeing
host paths. A failed chroot is checked to prevent any producer invocation.

The budget wrapper acquires `~/rey/build.lock` without waiting, then reads
`free -g`. It fails closed if the `Mem:` row's available value is below 6 GiB
or cannot be read. The cgroup memory cap is `min(12 GiB, available - 3 GiB)`;
swap is capped at 512 MiB. Each build uses `nice -n 19 timeout` with a maximum
timeout of 2,400 seconds and a 30-second kill grace. Command output is retained
under `~/rey/wave1/logs/`; cgroup events, peak memory, time output, source
hashes and traces are retained in the fresh external work directory.

All bootstrap compiler invocations use ordinary checked output and ordinary
process exit. The helpers do not change output permissions after a build. The
legacy Darwin-target helper remains separate from the Linux x64 native
qualification path and also uses ordinary process exit.

## B01 interfaces and limits

```sh
sh scripts/v04-selfhost-linux-x64.sh --self-test \
  --seed "$SEED" --source "$SRC" --work "$W/bootstrap"

sh scripts/v04-selfhost-linux-x64.sh --candidate \
  --seed "$SEED" --source "$SRC" --revision "$REV" --work "$W/candidate"
```

`--self-test` checks tampered and dynamic seed rejection, the seed-to-S3 dry
plan and exec allowlist, lock contention, low-memory admission, failed
isolation, unexpected exec rejection, producer-write-then-fail handling, and a
locked native tiny-fixture build with exact direct-execution output.
`--candidate` builds only S1. A multi-stage `--verify` is intentionally
unavailable in B01: section 4 of the council plan blocks full builds at the
current memory profile. No timeout or fast-exit result can substitute for
normal producer teardown.
