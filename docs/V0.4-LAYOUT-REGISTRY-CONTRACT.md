# Fixed tracing-layout registry, revision 1

This next runtime module is a prerequisite for the heap/collector. It consumes
trusted raw primitives and implements immutable fixed-payload tracing layouts.
It does not allocate managed objects or collect them, and does not represent
variable-length vectors, tagged variants or owned buffers yet. Those need
separate descriptor extensions before their managed runtime can ship.

## Source API

Implement `runtime-rey/layout/main.rey`, compiled as an authorized runtime unit:

```text
pub func layoutRegistryCreate(capacity: int): __rey_raw_address
pub func layoutRegistryRelease(registry: __rey_raw_address): void
pub func layoutRegisterFixed(registry: __rey_raw_address, payloadBytes: int,
    referenceOffsets: __rey_raw_address, referenceCount: int): int
pub func layoutCount(registry: __rey_raw_address): int
pub func layoutPayloadBytes(registry: __rey_raw_address, id: int): int
pub func layoutReferenceCount(registry: __rey_raw_address, id: int): int
pub func layoutReferenceOffset(registry: __rey_raw_address, id: int, index: int): int
```

IDs are sequential positive integers, at most 4294967295; zero is invalid.
They describe tracing layout, not nominal source identity. Identical layouts
may receive different IDs; source-level nominal checks remain in the compiler.
Registration copies the supplied offsets, so the caller may release its input
mapping afterwards. Reference offsets are relative to the object's payload,
which follows the managed ABI's 16-byte header.

Capacity may be zero, is bounded by the ID range, and has checked size arithmetic.
Payload bytes and reference count are nonnegative. Each reference offset must
be eight-byte aligned, at least zero, strictly greater than its predecessor,
and leave room for an entire eight-byte reference inside the payload. Count
zero permits a null offsets address; positive count requires a live readable
mapping containing that many i64 offsets. Native extents remain a trusted
caller precondition, while evaluator accesses check them.

An ID must be in `[1, count]` and an offset index in `[0, referenceCount)`.
All validation errors use `__reyRawFail`: 1001 capacity/size, 1002 invalid
descriptor, 1003 ID, 1004 reference index, 1005 full registry, 1006 corrupt
registry metadata. No invalid operation may silently produce an empty layout.

## Storage and ownership

One registry mapping has exact requested length `64 + capacity * 8`:

| Offset | Field |
| --- | --- |
| 0 | i64 magic 1380273234 |
| 8 | i64 capacity |
| 16 | i64 registered count |
| 24 | i64 original mapping length |
| 32..63 | reserved zero bytes |
| 64 + (id - 1) * 8 | typed raw address slot for the descriptor |

Each descriptor owns a mapping of exact length `32 + referenceCount * 8`:
payload byte size at 0, reference count at 8, reserved zero words at 16/24,
then copied i64 offsets from 32. The public API exposes no mutable descriptor
address. Registry table slots use typed raw address stores/loads. Descriptor
offset arrays contain integers and never act as roots.

Release consumes a live registry after every heap using its descriptors is
destroyed. Unmap each owned descriptor with its original size, then the registry
with its original size. Repeated release/use after release is a trusted caller
bug. Registration capacity is fixed in this slice; do not copy pointer-bearing
registry metadata using the raw byte-buffer growth routine.

## Evidence

Write all code and fixtures before testing. Check/lower/verify/evaluate the
actual runtime module and execute emitted Darwin/Linux arm64 programs. Cover
empty/no-reference layouts; multiple layouts; payload sizes not divisible by
eight; copied-input independence; exact ID/index boundaries; duplicate,
unsorted, negative, unaligned and out-of-bounds offsets; full registries; and
repeated register/release cycles that exceed the evaluator's 256 mapping slots
over time without retaining that many live mappings. Keep valid code within
the scalar/raw source subset (`while`, int/bool/void/raw types; no source
strings, Vecs, structs, assert or I/O). The host harness may use compiler APIs
and print evidence. This is a descriptor gate, not automatic tracing evidence.

The implemented module passes all 30 source fixtures through the coordinator's
combined raw/buffer/layout gate: 444 checks and 77 executions on each ARM64 OS,
including all 30 layout programs. Frozen evidence is
`build/v04/integration-layout-2/result.json`. Descriptors retain copied inputs,
exact release lengths and typed metadata addresses. Full registry validation
includes a quadratic duplicate-slot check; this is not yet a fast collector
lookup interface.

The seed-built compiler harness is run once per fixture. A combined harness
process was killed with signal 9 after several cases; fresh per-case processes
pass. The underlying cause is unconfirmed. This harness isolation is not a
claim that generated programs have automatic reclamation or bounded RSS.
