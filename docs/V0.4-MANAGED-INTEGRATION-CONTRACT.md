## Representation and lowering

Keep the verified scalar IR as the final machine-facing representation. A new
`ir::managed` module holds explicit annotations before managed lowering:

```text
ManagedField { name: string, offset: int, kind: IRTypeKind, layoutId: int }
ManagedLayout { id: int, key: string, payloadBytes: int, fields: Vec<ManagedField> }
ManagedFunction { functionId: int, referenceValues: Vec<int>,
                  parameterLayouts: Vec<int>, returnLayout: int }
ManagedAllocation { functionId: int, blockId: int, resultId: int, layoutId: int }
ManagedDerived { functionId: int, valueId: int, ownerId: int }
ManagedProgram { program: IRProgram, layouts: Vec<ManagedLayout>,
                 functions: Vec<ManagedFunction>, allocations: Vec<ManagedAllocation>,
                 derived: Vec<ManagedDerived>, allocateFunctionId: int,
                 storeReferenceFunctionId: int, collectFunctionId: int }
```

Layout IDs start at one in deterministic checked nominal-layout order. A field
uses eight bytes: i64, bool encoded as 0/1 i64, or canonical managed reference.
`layoutId` is zero for scalar fields/parameters/results and positive for reference
types. Layout identity uses checked source/module/name, never an unqualified
name or field spelling. Nullable struct references use the same layout and null.
Struct assignment/passing/return preserves shared mutable identity.

The first frontend sector covers nominal fixed-layout structs, nested/recursive
references, nullables, field access/mutation, identity comparisons, function and
CFG transfers. Other aggregate families are separate code-only follow-on
sectors; unsupported families must fail explicitly until implemented.

`lowerManagedProgram(checked)` creates ordinary verifiable IR plus annotations.
Three private trapping stubs have signatures `(i64)->raw` allocation,
`(raw,i64,raw)->void` reference-field store, and `()->void` collection poll.
Their IDs are recorded above; allocation calls carry constant layout IDs.
These stubs must be replaced before execution and never exposed as source APIs.
Every canonical reference definition (including formal/block parameters, nulls,
call and field-load results) is annotated; derived field addresses are distinct.
Derived addresses may only feed an adjacent field load/store, never cross calls,
edges or returns. Evaluate a store's owner then RHS before deriving its address.
Scalar field stores use raw i64 operations; bool loads compare the word with zero.
Reference stores use the private hook. User source receives no raw authority.

## Runtime APIs

`runtime-rey/managed/main.rey` imports layout/heap/gc and owns context/region
implementation. It has a void dummy `main` for library lowering. Public trusted
functions (all raw arguments/results below mean `__rey_raw_address`):

```text
managedCreate(registry: raw, stress: bool): raw
managedDestroy(context: raw): void
managedAllocate(context: raw, layoutId: int): raw
managedCollect(context: raw): int
managedRootPush(context: raw): int
managedRootSet(context: raw, index: int, object: raw): void
managedRootPop(context: raw, index: int): void
managedStoreReference(context: raw, object: raw, payloadOffset: int, value: raw): void
managedRegionCreate(context: raw): raw
managedRegionEnd(context: raw, region: raw): void
managedRegionAllocate(context: raw, region: raw, layoutId: int): raw
managedAllocateDestination(context: raw, destination: raw, layoutId: int): raw
managedLiveObjects(context: raw): int
managedLivePayloadBytes(context: raw): int
managedRequestedObjectBytes(context: raw): int
managedRegionRequestedBytes(context: raw): int
managedRegionObjectCount(context: raw): int
```

The registry is borrowed. Context owns its heap/collector and all active regions;
destroy regions, collector, heap, then caller releases registry. Root helpers
delegate to the GC shadow stack. RootSet registers heap/null references; a region
object itself is not individually heap-marked. Managed allocation automatically
collects by a checked allocation-byte budget, and stress mode collects before
every heap allocation. Recompute a bounded next budget from live bytes after
collection, minimum 65536. Allocation/root setup and field-store helpers do not
collect except managedAllocate/AllocateDestination/Collect as documented.

Regions use bump allocation in owned RW mappings and bulk release. Preserve the
standard object header/payload with header bit 33 set for region objects; layout
ID remains low 32 bits, payload size at 8, fields at 16. Region objects never enter
heapSweep. Every region object's reference fields have parallel typed root cells:
heap children are roots, null/region children store null in those cells. Update
the shadow cell on every field write. Constructor fields start typed-null.
Region-to-region stores require equal or older destination lifetime for the
value; heap-to-region stores reject before mutation. Use context-owned active
region/object metadata and monotonic creation serials; no pointer-to-int casts.
Unknown or escaping objects are placed on the heap before allocation.

Extend gc with non-LIFO borrowed root ranges so a callee can construct directly
in a caller's region without trapping caller-owned roots above its own frame:

```text
gcRegisterRootRange(collector: raw, addresses: raw, count: int): raw
gcUnregisterRootRange(collector: raw, range: raw): void
```

Each range owns its linked metadata, borrows initialized typed heap/null cells,
and can be unlinked independently. Range storage outlives registration. Trace
these cells with the same mark-before-enqueue worklist. GC context offset 40
becomes the typed range-list head; offsets 48..63 stay reserved. Create must
initialize it. Destroy rejects outstanding ranges. Existing roots/stats remain
compatible; document extra range metadata separately. RegionEnd unregisters
ranges before unmapping their storage. Use RawFail 2201 size, 2202 managed
metadata, 2203 invalid field/lifetime, 2204 invalid region; GC range errors 2105.

## Root transformation

`ir::managed::roots::lowerManagedRoots(module, bindings, placements, stress)`
returns a fresh `Result<IRProgram,string>` after runtime linking. It validates
annotations and input IR, uses semantic liveness, and rejects missing/duplicate
canonical reference metadata and invalid derived-address uses. No input mutation.

Every user function receives appended hidden context and destination raw
parameters. Verified safepoint liveness colors canonical references into shadow
slots: references that must be published together receive different slots;
nonoverlapping references may share one. Unused references need no slot. A
500,000-unit per-function coloring budget safely falls back to one slot per
annotated reference. Its prologue pushes one null slot per selected color.
Indices are SSA values dominating all blocks. Before each
potentially collecting user call/allocation/poll, clear frame roots then publish
exactly liveBefore canonical references, including call arguments. Do not load
undefined values. Clear each shared slot once before writing live references;
a dead alias must never clear a live value in the same slot. Stress mode also
collects after publication before user calls.
All runtime helpers used during publication are non-collecting. Callees root
parameters before their first collecting call. Returned values reach the caller
before the next collection; return cleanup itself never collects.

Pop each selected slot once in reverse order on every return; end the function region before
popping frame roots. Rewrite allocation/store/poll hooks to runtime functions.
Scalar and raw runtime functions are not themselves rewritten. Existing calls
among user functions receive hidden arguments. Backend support must accommodate
the hidden parameters without reducing the accepted eight source parameters.

Generate a no-argument void entry wrapper: create/register all layout descriptors,
create managed context, call original main with context/null destination, destroy
context, release registry, return. No global context, conservative stack scan,
integer pointer forging, leaked permanent roots or native external compiler.

The revision 1 baseline of `RuntimeBindings` contains integer function IDs named `create`, `destroy`,
`allocate`, `collect`, `rootPush`, `rootSet`, `rootPop`, `storeReference`,
`regionCreate`, `regionEnd`, `regionAllocate`, `allocateDestination`,
`layoutCreate`, `layoutRegister`, `layoutRelease`. The coordinator links the
runtime IR into `ManagedProgram.program`, remaps its function IDs, and supplies
these bindings. Original user/hook IDs stay unchanged. The implemented
[aggregate follow-on](V0.4-MANAGED-AGGREGATES-CONTRACT.md) additionally requires
`layoutRegisterVariable` and the `hooks` binding vector.

## Placement and destination construction

`ir::managed::placement::planManagedPlacement(module)` returns a fresh plan:

```text
enum ManagedStorage { Heap, Region, Destination }
ManagedAllocationPlacement { functionId: int, resultId: int, storage: ManagedStorage }
ManagedCallPlacement { functionId: int, blockId: int, instructionIndex: int,
                       storage: ManagedStorage }
ManagedPlacement { allocations: Vec<ManagedAllocationPlacement>,
                   calls: Vec<ManagedCallPlacement>, regionFunctions: Vec<int> }
```

Prove placements conservatively through reference aliases, CFG arguments, field
stores and returns. Unknown reference arguments/callees escape. Propagate an
owner's escape to references stored in it; preserve every alias and cycle.
Unknown lifetimes use Heap. A returned fresh component with only return escape
may use Destination; null destination means heap. Calls whose result is proven
local may receive the caller's region; returned-only results may inherit its
destination. No runtime copying/relocation is called promotion.

A return through an aliasing call must carry that caller's escape back to its
originating allocations. A borrowed formal returned by a callee does not by
itself prove an escape beyond the caller. Reference-field loads without precise
stored-value provenance conservatively force the canonical owner and its stored
children to the heap. Scalar field reads do not require that fallback. This
keeps loaded children from outliving a region whose ownership was not proved.

Initially use per-invocation regions only for proven local allocation/call
sites outside CFG cycles. Cyclic sites fall back to the tracing heap until an
iteration-lifetime proof and cleanup exists. This bounds scratch retention and
does not pretend a function arena solves long-running loops. A subsequent
code-only sector may add proven iteration regions under the same test barrier.

## Machine argument and frame limits

Managed user calls append context and destination after source arguments. The
direct backends accept at most sixteen machine arguments; ARM64 uses x0-x7 and
eight-byte stack slots thereafter. Incoming stack arguments are read relative
to the saved frame pointer. Outgoing argument storage precedes value slots and
edge-copy scratch storage. The x64 emitter retains its scalar SysV policy.
ARM64 frames up to 32768 bytes use aligned, bounded stack adjustments; larger
frames fail explicitly. Fixed slot frames below the former 4080-byte limit keep
their instruction encoding. Write boundary and executable clobber fixtures for
both default and reused slots before the global barrier opens.
