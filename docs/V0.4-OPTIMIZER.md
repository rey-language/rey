# v0.4 optimizer pipeline

The passes in `rey-compiler/src/ir/optimize/` rewrite verified IR and verify the result before returning it. Each pass is off unless a caller sets its flag. `optimizeProgram` runs enabled passes in a fixed order: fold, propagate, specialize, propagate, inline, stream fusion, copy, redundant loads, redundant zero stores, ranges, bounds checks, constant-branch simplification, dead values.

`foldConstants` is unchanged. It still folds only inside a block and keeps every instruction. The production `ir-main` and `native-main` drivers still call only that pass. The integration driver in `tests/v04/opt-pipeline/main.rey` is what selects the new passes with `--passes`.

## Passes

- **fold** — existing intra-block constant folding.
- **propagate** — constants agree on every incoming edge, then checked arithmetic and comparisons fold. Overflow, division by zero, and `INT64_MIN / -1` stay as instructions.
- **copy** — `x+0`, `x-0`, `x*1`, and `x/1` forward to `x`. Those identities cannot trap.
- **dead** — removes an unused const, comparison, or checked operation only when the operation is known not to trap. Unused `1/0` stays.
- **range** — signed ranges for straight-line and acyclic joins. Add and subtract use the four corners and stay unknown if any corner traps. Multiply, divide, and remainder stay unknown unless both sides are a single non-trapping value. A value carried by a block in a cycle widens to unknown, so a growing induction compare is left in place. A comparison becomes a constant only when the analysis stops changing and every value in both ranges proves it. If it does not settle within 16 rounds, only constants remain.
- **inline** — inlines a callee of at most 16 pure scalar instructions and 6 blocks, with no calls and no raw operations. The callee must return on at least one path, and every return must match the call's result shape, so the continuation stays reachable. Unreferenced functions are then dropped.
- **specialize** — clones a single-block pure callee when a call argument is a constant, and retargets that call.
- **loops** — a branch on a constant bool becomes a jump. Blocks that the verifier would reject as unreachable are removed. This is how a constant loop exit disappears.
- **bounds** — a comparison dominated by the same comparison on one predecessor edge becomes the corresponding constant. The proving branch has to be in a different block: a block's own backedge describes the previous iteration. The branch stays, so both targets remain reachable until `loops` runs.
- **loads** — in one block, a later load of the same address SSA value and width reuses a store or an earlier load. The replacement is the surviving value, including when an earlier load in the chain was removed. Any store clears the table, because a different address SSA value may alias. A call, map, unmap, fail, or syscall clears it too. A load does not.
- **zero** — a `raw.store.i64` of constant 0 is removed only when the next memory operation in that block is a `raw.store.i64` to the same address SSA value. A call, load, or store of another address keeps the zero.
- **fuse** — inlines `parseCsvField`, `keepCsvRow`, and `addCsvTotal` into their caller when they meet the inline limits. A function named `sumBufferedCsv` may also drop a straight-line `raw.map` / store / load / `raw.unmap` of that base when the load is exactly the stored value. Each removed load in that function is replaced by its own stored value. Checked adds are not moved across separate loops.

## Streaming fixture

`tests/v04/streaming/sample.csv` is the row schema `index,value,keep`. The scalar programs generate rows with `value = index` and keep even indexes. They do not call the managed CSV parser. Fusing that parser would require string and vector operations that are opaque runtime calls today; this slice does not reorder those calls and does not claim the standard-library parser is allocation-free.

`scripts/v04-opt-test.py` writes `perf.json` next to its other output when the run finishes. The file records native Darwin arm64 wall time, image size, compiler time, IR call count, and `raw.map` count for `tests/v04/streaming/sum.rey` with passes off and with the streaming passes on. The ratio is that measurement only.

## Limits

Region and lifetime metadata are not updated by these passes. The passes are not on the region runtime path. Inlining refuses raw operations and calls, so it does not move a managed allocation hook. Specialization is limited to pure scalar leaves. Stream fusion does not merge two checked reductions into one loop, because that would reorder traps. Redundant zeroing removes only an i64 store of constant 0 that the next memory operation in the same block overwrites at the same address; it does not remove object setup or metadata initialization.

Borrowed field views, incremental parsing of the managed CSV reader, SIMD, and parallel execution are not implemented. Those need lifetime facts, string and vector operations that are opaque calls, or a legality and error model this IR slice does not have. No new IR operation was added.
