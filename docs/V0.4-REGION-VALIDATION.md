## Implemented production path

- `runtime-rey/regions` owns a program region plus LIFO invocation/iteration
  regions, per-site allocation groups, 4 KiB-or-larger chunks, dependency edges,
  and address-preserving promotion. Ending a region releases only groups and
  metadata still owned by that region.
- `runtime-rey/managed` is a non-collecting facade. `Heap` placement maps to
  `managedAllocateProgram`; `Stack` remains reserved for a later proof. The old
  root helpers validate the context and are no-ops; they do not publish roots.
- `runtime-rey/containers` allocates helper storage in the current region.
  Container methods and unknown callees remain conservative program-region
  escapes; see the limitation below.
- `rey-compiler/src/ir/managed/regions` emits hidden context/destination
  parameters, group ids, store hooks, and return promotion before region end.
  Null promotion is a no-op; a null destination means the program region.
- `rey-compiler/src/ir/managed/lifetime` verifies placement, escape, region-end
  dominance, direct-store bypass, and cyclic placement before lowering.
- `rey-compiler/src/ir/managed/link` loads only layout, regions, managed and
  containers; the legacy `buildManagedProgram(regions=true)` path fails closed.
- The managed driver defaults to `--regions`; `--no-regions` remains a legacy
  experiment and is not a v0.4 acceptance path. `--gc-stress` is rejected by the
  region managed driver.

### Region-source fixtures

These seven fixtures were added for the container/identity/return boundary.
All seven pass natively on both ARM64 targets in every mode. The source
evaluator is capped at 1,000,000 steps; six fixtures are explicitly native-only
and their measured evaluator steps are retained in the manifest. Container
method calls are managed hooks, so the containers in these fixtures
conservatively reach the program region; the fixtures assert identity, aliases,
cycles, container growth and return paths under that placement, not
caller-region container retention.

| Fixture | What it checks | Evaluator steps |
| --- | --- | ---: |
| `container-cycle.rey` | vector/map cycle, aliases, identity | 556,735 |
| `container-return.rey` | container built in callee and returned | 2,000,734 (native-only) |
| `container-nested.rey` | nested struct/vector/map, null tail, cycle | 2,478,393 (native-only) |
| `container-graph.rey` | recursive container graph and aliases | 7,123,419 (native-only) |
| `container-region-return.rey` | callee-local struct plus returned container under conservative placement | 3,028,589 (native-only) |
| `container-region-local.rey` | local container construction/use and region-end path | 3,966,447 (native-only) |
| `container-caller-region.rey` | nested callee-to-caller container returns and aliases | 2,130,881 (native-only) |

Native-only is an evaluator policy, not a skipped native assertion: the same
fixture is emitted and executed for Darwin and Linux ARM64 in all four modes.

### Region runtime fixtures

The 17 direct runtime fixtures cover allocation groups, program-region
survival, group separation, promotion address identity, older/equal source
no-op, null promotion, dependency chains, cyclic promotion, store promotion,
older-store dependency recording, destination construction, LIFO/program/double
region-end rejection, container current-region allocation, repeated-request
plateau counters, and long-lived graph-retention counters. The null fixture
checks `managedPromoteReference(context, null, null)` and a null object with a
live child target; both return null with zero promotions, dependencies, and live
objects.

## What is not established

- **Conservative container retention.** Container method/hook calls and unknown
  callees are not named in the placement callee model, so container values that
  cross those boundaries conservatively reach the program region. Hook
  allocations still use the current region. The new fixtures establish
  correctness, identity, aliases, cycles and promotion; they do not establish
  caller-region retention or an RSS plateau for arbitrary container graphs.
- **No RSS or timing claim.** The repeated-request and long-lived-graph
  fixtures assert runtime counters; they do not measure resident memory or
  throughput.
- **Platform boundary.** Native execution is Darwin arm64 and Linux arm64 in
  Docker. Native x64 hardware, macOS Intel, Windows, self-hosting, structured
  tasks, and release performance remain out of scope. The x64 gate is structural
  only.
- **Evaluator boundary.** The source evaluator is capped at one million steps.
  The six native-only region-source fixtures are above that cap; all native
  assertions still run. Debug-mode measured steps are 0.56M to 7.12M and are not
  a performance result.
- **Historical managed suites.** `managed-runtime`, `managed-containers`,
  `managed-extra`, and the old teardown/roots/placement/link harnesses depend on
  the retired collector/root API or the removed `sources/managed/regions`
  layout. They are not v0.4 acceptance. `scripts/v04-memory-test.py` defaults to
  `fixed-heap,fixed-gc`; the retired managed suites require the explicit
  `--historical-managed` switch. The fixed heap/collector suites remain
  historical regressions and pass 402 / 402 checks.
