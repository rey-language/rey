## Implemented production path

- `runtime-rey/regions` owns a program region plus LIFO invocation/iteration
  regions, per-site allocation groups, 4 KiB-or-larger chunks, dependency edges,
  and address-preserving promotion. Ending a region releases only groups and
  metadata still owned by that region.
- `runtime-rey/managed` is a non-collecting facade. `Heap` placement maps to
  `managedAllocateProgram`. `Stack` is selected for a non-cyclic local of at
  most 256 bytes with no reference field, no variable tail, and an address
  that is not published. Lowering puts it in a kind-4 cohort with a 4096-byte
  budget. The old root helpers validate the context and are no-ops; they do
  not publish roots.
- `runtime-rey/containers` allocates helper storage in the current region.
  Named container hooks and `managedAllocateSized` follow escape analysis.
  A container returned to a caller that does not publish it further is placed
  in that caller's region. An unknown callee still uses the program region.
- `rey-compiler/src/ir/managed/regions` emits hidden context/destination
  parameters, group ids, store hooks, and return promotion before region end.
  Null promotion is a no-op; a null destination means the program region.
- `rey-compiler/src/ir/managed/lifetime` verifies placement, escape, region-end
  dominance, direct-store bypass, and cyclic placement before lowering.
- `rey-compiler/src/ir/managed/link` loads only layout, regions, managed and
  containers; the legacy `buildManagedProgram(regions=true)` path fails closed.
- The managed driver defaults to `--regions`; `--no-regions` remains a legacy
  experiment and is not a v0.4 acceptance path. `--gc-stress` is rejected by the
  region managed driver.

Remaining promotion limit: objects allocated by one instruction share one
group. `allocationGroupId` in
`rey-compiler/src/ir/managed/regions/main.rey` returns `index + 1` for that
allocation, so a loop cannot give each iteration its own group. A
region-dependency cycle still moves a group that stores a reference into the
promoted set, which is what `promotion-cycle` requires. Groups in that cycle
with no such reference stay behind and are released at region end. The move
does not widen to every group of the source region.

## What is not established

- **Unknown callees.** A callee that is not a user function and not a named
  container hook still publishes its reference arguments and its returned
  reference to the program region. The planner assertion covers that fallback.
- **Full historical matrix not repeated.** `scripts/v04-managed-test.py` was
  not re-run for the current work. The live compiler does build on Linux x64,
  but current region-source evidence is limited to the 16-program focused run
  above. The 15 named direct runtime fixtures passed after final teardown; the full
  historical runtime suite was not rerun. The historical
  native and IR drivers for measurements above were built from a snapshot with
  the then-current placement, lifetime, and region lowering.
- **No timing or C comparison.** The RSS table is resident size for these four
  loops only. It is not a throughput result and not the 1.25x C target.
- **Platform boundary.** The historical full matrix covers Darwin arm64 and
  Linux arm64 in Docker. Current Linux x64 native evidence is limited to the
  focused checks above; macOS Intel, Windows, complete cross-platform release
  gates, structured tasks, and release performance remain unverified.
- **Evaluator boundary.** The source evaluator is capped at one million steps.
  The six native-only region-source fixtures are above that cap; all native
  assertions still run. Debug-mode measured steps are 0.56M to 7.12M and are not
  a performance result.
- **Historical managed suites.** `managed-runtime`, `managed-containers`,
  `managed-extra`, and the old teardown/roots/placement/link harnesses depend on
  the retired collector/root API or the removed `sources/managed/regions`
  layout. They are not v0.4 acceptance. `scripts/v04-memory-test.py` defaults to
  `fixed-heap,fixed-gc`; the retired managed suites require the explicit
  `--historical-managed` switch. The fixed heap/collector suites remain
  historical regressions and pass 402 / 402 checks.
