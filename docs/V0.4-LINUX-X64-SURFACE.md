# Rey v0.4 Linux x64 SPEC surface

This is the native coverage ledger for the normative families in [`SPEC.md`](../SPEC.md).
Each numbered heading in `SPEC.md`, including parent sections, has exactly one row below.
The paths are source-relative and are checked by `tests/v04/linux-x64-spec/run.sh --lint`.

The listed fixtures are representative native compiler anchors. A row marked `partial`
does not claim section conformance: its named issue and owner identify the remaining
native Linux x64 oracle work. `native-check` fixtures cover compiler acceptance or
rejection; `native-run` fixtures are native Rey test programs whose expected result is
also listed. Negative cases must carry an expected-result path. The existing lexer
driver contains assertions for both accepted and rejected lexical inputs, so it appears
under both polarities.

The JSON blocks are the canonical machine-readable manifest. The lint checks every
numbered SPEC heading, all paths and result files, every issue owner, and the exact
example stdout below. It also mutates an in-memory copy to prove that a deleted family
row, negative expected result, or example stdout record is rejected.

## Scope of this slice

`--lint` is intentionally compiler-free. It verifies inventory and evidence links, then
writes a hash-keyed report to the requested external output directory. Wave 5 L01 and
later feature slices can replace named gaps with specific native cases as ownership is
handed forward. The four example stdout records remain the fixed release oracle.
