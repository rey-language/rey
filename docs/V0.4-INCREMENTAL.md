# v0.4 incremental compilation

This note is the M7 cache surface. It does not change production memory.
Production managed memory stays region-only. No timing number here is a
measurement. `observation: not measured` is the required line when a report
has no accepted sample file.

The on-disk unit record remains `rey-cache 1`, as in the incremental
contract. A source-text digest alone is not a cache key.

## Driver entry

`rey-compiler/src/ir/cache/main.rey` publishes one build function:

```
pub func compileWithCache(root: string, buildId: string, maxBytes: int, units: Vec<IncrementalUnit>, reportPath: string): Result<IncrementalResult, string>
```

`IncrementalUnit` is `{ snapshot: UnitSnapshot, freshPayload: string }`.
`IncrementalResult` is `{ output, report, kind, rebuiltUnits, hitUnits, recovered, relink }`.

The experimental drivers do not call this yet. The flags they should accept
are `--cache-dir <root>` and `--cache-report <path>`. Capy also sets
`REY_CACHE_DIR` and `REY_CACHE_REPORT` to those same paths. `buildId` must be
a single path segment, unique per concurrent build. `maxBytes` must be
positive. A 256 MiB budget is `268435456`.

Set every unit's `compilerAbi` to `compilerCacheIdentity(compilerHash)`. The
hash is mixed into the ABI string. An empty or non-token hash is ignored and
the plain `rey-ir-cache-1` ABI is used, which will not invalidate on a
compiler change. The object key is the SHA-256 of the unit source, function
body digests, dependency interface digests (effect, layout, inline,
specialization), compiler ABI, runtime ABI, target, semantic flags, and
optimization. Callers are not part of a callee's body digest.

`freshPayload` may be empty only for units `planRebuild` does not rebuild.
`compileWithCache` reads `<root>/manifest.txt` from the previous success. The
first build, a target or compiler-hash change, or an added or removed unit is
a full rebuild. A corrupt manifest, a corrupt record, a payload collision, or
a miss on a unit that should have hit does not return that payload. Pass a
fresh payload for every unit and the same call falls back to a clean rebuild
(`recovered` is true, `kind` is `full`). If a payload required for that
fallback is empty, the function returns an error and no output.

The linked `output` is `rey-link 1` plus each unit id, payload length, and
payload, sorted by unit id. A no-op returns the stored link only when it
still matches that text. A one-function edit recompiles the dirty unit,
reuses cached payloads for the rest, and relinks. That output matches a
clean build that was given the same real payloads.

The report written to `reportPath` starts with `rey-cache-report 1`. Explain
lines use `established:`, `estimate:`, `observation:`, and `unavailable:`.
`observation: not measured` is always present. A corrupt report is not a
successful explanation.

## Invalidation

`planRebuild` still decides the set:

- One function body change rebuilds that unit. Callers stay cached when the
  effect, layout, inline, and specialization digests are unchanged, and the
  link is rebuilt.
- A change to any of those four digests rebuilds the unit and every current
  unit that reaches it. An unrelated unit stays a hit.
- A compiler hash, ABI, target, flag, or optimization change is a full
  rebuild. Old objects are not read.

## Capy

`capy build` hashes the compiler binary, the entry, project `.rey` files,
`capy.toml`, the flags, and the toolchain standard library. A no-op skips
the compiler when that identity is in a valid `capy-incremental 1` record
and the output digest matches. The report says `compiler was not started`
and `cache hit for every unit`.

A compiler-hash change, a corrupt record, a flag change, or a toolchain or
manifest change is a full rebuild. One changed function is `one-function`.
Other source changes are `dependency`. Importers of a changed file are an
estimate, because Capy does not have effect digests. Unchanged files are
hits. `--no-incremental` forces a compiler run.

Capy still starts one compiler process for every non-noop build. The driver
has not been wired to `compileWithCache`, so that process is whole-program
and its executable is the clean build of the current sources. The report
names the units the cache would rebuild. `capy explain` prints the report
next to the incremental record. A report that does not start with
`rey-cache-report 1` is corrupt and is not accepted.
