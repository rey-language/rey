# Managed memory integration validation

The implementation contracts are
[compiler roots and regions](V0.4-MANAGED-INTEGRATION-CONTRACT.md) and
[aggregate storage](V0.4-MANAGED-AGGREGATES-CONTRACT.md).
All implementation sectors and fixtures were written before the coordinator
opened the global barrier. Integration tests and observed repairs are complete
for this experimental slice. The final main matrix passes 1,429 checks with
370 native images; the supplemental matrix passes 534 checks with 160 images
and 40 interpreted teardowns. Both include actual Darwin/Linux ARM64 execution.
Managed runtime passes 191 checks per slot mode, fixed heap/collector 402 per
mode, and raw/layout 444. See the [parallel ledger](V0.4-PARALLEL-PHASES.md)
for exact frozen evidence, regression counts and remaining release gates.

## Test barrier

All workers write implementation code and executable assertions before any
compiler, build, test, fixture, or benchmark runs. The coordinator freezes all
sectors and announces the barrier before deploying validation. Subsequent fixes
require fresh relevant results; results identify their frozen source snapshots.

## Source and compiler gates

`python3 scripts/v04-managed-test.py --code-complete --output-dir
build/v04/managed-integration/<fresh-name> --linux-docker` builds the roots,
placement, and linker unit fixtures plus source drivers and a teardown harness.
It runs manifests from `managed-aggregates`, `managed-patterns`, and
`managed-smoke` in five modes:

| Mode | Regions | Forced collection | Constant folding | Slot reuse |
| --- | --- | --- | --- | --- |
| heap | off | off | off | off |
| placed | on | off | off | off |
| stress-heap | off | on | off | off |
| stress-placed | on | on | off | off |
| stress-optimized | on | on | on | on |

Compile failures require diagnostic substrings. Runtime failures retain bounded
interpreter checking and generated process status checks. Cases marked
`teardown:true` additionally collect after source main returns and assert zero
frame roots, region storage, registered region root ranges, live heap objects,
live payload, and requested object mappings before context destruction. The
test-only instrumentation never authorizes source code to use raw memory.
The ordinary source interpreter is bounded at one million steps; the teardown
interpreter is bounded at four million. Any exhaustive fixture omitted from an
interpreter must record its observed limit and retain both native executions.
An explicit `teardown_native_only` policy also requires a measured reason and
still executes the instrumented zero-live-storage assertions natively. Small
family smoke fixtures remain interpreted, including under forced collection.

The exhaustive omission policies retain measured failures from earlier frozen
snapshots. Root-cell compaction can reduce evaluator work; these policies do not
claim that every omitted case still exceeds the current interpreter limit.
Every omitted interpreted execution retains native execution on both ARM64
operating systems. Cases marked for teardown also retain the instrumented
zero-live-storage assertions on both systems.

After the main run has built frozen drivers, run the supplemental suite with
`python3 tests/v04/managed-extra/run.py --drivers
build/v04/managed-integration/<fresh-name> --output-dir
build/v04/managed-extra/<fresh-name> --linux-docker`. Its eight fixtures run in
all five modes, with all 40 interpreted teardowns required and no interpreter
omissions. Each mode executes normal and instrumented Darwin/Linux images,
giving 160 native artifacts. Linux execution occurs in a final batch; emitting
an ELF image alone does not count as execution.

## Runtime and backend regressions

`python3 scripts/v04-memory-test.py` covers the old fixed heap/collector and the new
managed runtime/containers. Run default and `--reuse-slots` separately. Explicit
interpreter omissions must name the bounded workload and retain native checks.

`python3 tests/v04/native-storage/run.py --suite arguments` exercises eight, nine, ten,
and sixteen machine arguments, hidden pointers, a frame requiring multiple
stack adjustments, and rejection beyond the supported argument count. Its
default suite retains the existing slot clobber and frame reduction assertions.
Both suites emit default/reuse Darwin ARM64, Linux ARM64, and scalar Linux x64
images. Linux x64 emulation is recorded separately from native hardware.

The existing scalar/native, raw/layout, constant folding, arithmetic oracle,
module graph, and frontend comparison gates remain required regressions.

## Evidence boundaries

The historical v0.3.1 seed may invoke its historical toolchain to build harnesses.
Generated source builds and executable images run with compiler tools absent
from PATH. The new runtime and backend are implemented in Rey. These gates do
not establish native self-hosting, concurrent collection, Windows support, a
complete language surface, or measured application speed/RSS improvements.
Region placement currently covers proven fixed allocations outside CFG cycles;
uncertain and dynamic lifetimes use the tracing heap. Reference-field loads
conservatively keep their owner and stored children on the heap. Promotion uses construction in a
proven caller destination; moving existing aliased graphs is not implemented.
