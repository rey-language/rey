- Track slab ownership and occupancy, retain released small blocks on class free lists, and unmap wholly empty slabs after unlinking their cached blocks. - Report mapped slab bytes, reusable cached block bytes, and the requested bytes and count of live direct blocks separately. Cached bytes are a subset of slab bytes; direct requested bytes exclude OS page rounding and are not RSS.
- Reuse the promotion indegree array for cycle classification and index region and group membership by address. Object discovery and graph walks still have costs that need measurement.
- For large managed programs, try bounded local lifetime proofs for fixed allocations. Proven nonescaping allocations use a short-lived stack cohort or invocation region; other allocations keep their program lifetime. A transitive call-graph summary rejects unknown calls that could allocate into the ambient region. The completion verifier recomputes that summary and rechecks each proof, cohort budget, and region-function list. The stack cohort is region-backed, not machine-stack storage. A rejected destination proof falls back to program lifetime.
- Keep references in the program region when their function converts an address to an integer, and independently reject such conversions of non-program allocations and their derived addresses in the lifetime verifier. Block cohorts reject untracked derived addresses and unbounded ambient effects; automatic loop cohorts without a verified site are disabled. Focused negative lifetime fixtures pass; broader verification remains necessary.
- A separate bounded interprocedural escape summary is available through `--experimental-escape-summary`. It is off by default, requires the embedded runtime, and includes restricted proofs for acyclic leaf functions that create and read temporary containers and for fixed allocations that die within a call-free phase block. Incomplete summaries fall back conservatively, and selected placements are rechecked during completion verification.
- The experimental proof trusts the checked-in runtime hook implementations. The public low-level IR and completion APIs do not authenticate caller-supplied runtime IR; their callers must preserve that trust boundary when enabling the proof.
- Index managed function lookups during lowering and function lookup when sizing the lifetime analysis budget.
- Cache the most recent byte-to-string conversion per lexer, and lazily use a bounded byte table for longer, varied inputs. This avoids repeated conversions without shared mutable state; after table activation at most 127 pre-table misses and 256 table strings are created per lexer. Values can remain in their region until it ends, especially on the large-program fallback; short sources keep the one-entry behavior.
- Reuse block-local x64 RAX results and RCX operands when they still contain the required SSA values. Values remain stored in their slots; caches reset at block boundaries and around clobbering calls. This is not cross-block register allocation.

## Still needed

- Verify the experimental interprocedural lifetime analysis and expand coverage beyond its conservative fallback. The large-program path still leaves many hook-created vectors, maps, and strings in the program region; add proven phase-scoped lifetimes and safe destination construction for those objects.
- Extend native coverage of slab occupancy, release, alias identity, and promotion interactions; measure memory and mapping churn on repeated bursts.
- Measure and reduce region-context teardown cost. During the S1-to-S2 build, the executable image was written but shutdown spent minutes faulting swapped pages; context destruction validates and walks region groups and cached blocks. A faster teardown must still release direct mappings and preserve corruption checks.
- Verify indexed promotion membership preserves aliases, cycles, and address identity. Reduce metadata and container backing-buffer retention without invalidating aliases.
- Expand direct packed binary output and seed-compatible fallback coverage, and evaluate a real internal byte buffer beyond the trusted compiler self-host path.
- Verify the register allocation paths and ARM64 unwind behavior, extend x64 allocation to other targets, and integrate broader optimization with verified lifetime metadata. Evaluate compiler data structures and incremental reuse with measurements.
- Complete target-specific host runtime integration and verify standalone packaging and bootstrap reproducibility across targets.
- Make generated Unix executables runnable without a separate `chmod +x`; current managed output creation uses ordinary data-file permissions, and focused execution checks set the executable bit explicitly.
- Add physical-memory and timing measurement workloads, including large bursts and both sides of the function-count cutoff. Compare compiler time, peak RSS, binary size, and generated-program performance against matched baselines.
- Resolve the remaining raw-pointer API ABA case and cross-context address-reuse limitation, and decide how long-running programs should handle the token serial bound.

This fixed point uses trusted fast exit; do not infer normal teardown, correctness across targets, or release readiness from these focused results.
