# Managed aggregate families, code-only follow-on contract

The global no-build/no-test barrier in MANAGED-INTEGRATION revision 1 applied
across this follow-on and was opened after all sectors were written. See
[validation status](V0.4-MANAGED-VALIDATION.md). Fixed structs alone do not cover containers.
Write all code and assertions before integration testing. Keep unsupported
scalar/operation cases explicit; never silently change SPEC.md semantics.

## Schema additions

In `ir::managed`, add:

```text
ManagedVariableLayout { layoutId: int, tailKind: int }
ManagedHook { functionId: int, runtimeName: string, mayCollect: bool }
```

Append `variableLayouts: Vec<ManagedVariableLayout>` and
`hooks: Vec<ManagedHook>` to ManagedProgram. Layouts otherwise retain revision 1.
Variable layout payloadBytes is its minimum fixed prefix (8 for the initial
string/backing-storage layouts). tailKind 1 is an untraced byte tail; 2 is a
typed-reference tail with an initialized-element count at payload offset 0,
elements starting at payloadBytes, stride eight. A reference tail requires an
eight-byte-aligned prefix and reserves offset 0 exclusively for its count;
fixed reference fields cannot overlap that word. Registration and subsequent
descriptor validation both reject violations. Fixed-prefix reference offsets
still trace normally. Tail allocation capacity is derived from actual payload
bytes; trace count must fit capacity. No scanning unused capacity or integer bits.

ManagedHook identifies a private verifiable trapping stub. Its runtime function
has the same signature with a context raw parameter prepended. Root lowering
publishes before mayCollect hooks and rewrites them to the resolved runtime ID.
All raw results/arguments are canonical managed references; no interior/raw-owned
buffers cross this interface. Placement treats hook reference arguments as
potentially escaping and hook reference results as heap/unknown. Fixed struct
allocation/store/poll hooks remain as before. Dynamic backing allocations never
receive inferred fixed-layout region placement.

Roots RuntimeBindings gains `layoutRegisterVariable: int` and
`hooks: Vec<ManagedHookBinding>`, where
`ManagedHookBinding { functionId: int, runtimeFunctionId: int, mayCollect: bool }`.
Validate arity/type equality with the prepended context and unique hook IDs.
Coordinator supplies bindings while linking the independently checked runtime.
Startup registers fixed or variable descriptors in the same deterministic ID
order. Every metadata constructor in fixtures/linker must include new vectors.

## Runtime variable layouts

```text
layoutRegisterVariable(registry, minimumPayloadBytes, offsets, referenceCount, tailKind): int
layoutTailKind(registry, layoutId): int
heapAllocateSized(heap, layoutId, payloadBytes): raw
managedAllocateSized(context, layoutId, payloadBytes): raw
```

Raw parameters use the existing trusted raw type. A fixed layout accepts only
its exact size. Variable sizes must be at least the minimum; reference tails
must contain a whole number of eight-byte slots. Reserve descriptor word16
for a distinct magic-tagged tail kind (1380273301 or 1380273302), word24 for the
minimum/tail offset; fixed descriptors retain both zero. Existing arbitrary
reserved-word corruption tests must still reject. Heap object validation uses
actual header payload length with the matching layout policy. GC validates
and traces only initialized reference tail elements. Existing fixed APIs remain.
Region allocation currently rejects variable descriptors; unknown dynamic
lifetimes use the managed heap, preserving reclamation and bounds.

## Strings/chars

String layout: fixed prefix len:i64 at payload0, byte tail at8, including a
trailing NUL beyond logical length. Preserve every byte, including 0 and255.
Chars use i64 machine storage but the checker retains distinct char semantics.

Trusted helpers in `runtime-rey/containers/main.rey`:

```text
managedStringLength(context, value): int
managedStringByte(context, value, index): int
managedStringEqual(context, left, right): bool
managedStringConcat(context, stringLayoutId, left, right): raw
managedStringSlice(context, stringLayoutId, value, start, end): raw
managedStringFromInt(context, stringLayoutId, value): raw
managedStringToInt(context, value): int
managedStringContains(context, value, needle): bool
managedStringIndexOf(context, value, needle): int
managedStringStartsWith(context, value, prefix): bool
managedStringEndsWith(context, value, suffix): bool
managedStringCase(context, stringLayoutId, value, upper: bool): raw
managedStringTrim(context, stringLayoutId, value): raw
managedStringRepeat(context, stringLayoutId, value, count): raw
managedStringReplace(context, stringLayoutId, value, from, to): raw
managedStringPad(context, stringLayoutId, value, width, pad, left: bool): raw
```

All context/object arguments and string results are raw; numeric ones int.
Allocation helpers are mayCollect. Nonallocating reads/search/equality/conversion
are not. Construction temporaries must be rooted explicitly inside runtime
helpers when another allocation may collect. Caller input references are already
published by compiler roots. Follow SPEC byte/clamping/error semantics exactly,
including empty replace needles and INT64_MIN formatting/overflow guards.

String literals lower to managedAllocateSized plus byte stores, logical len and
trailing NUL, with source decoding left to the checked AST. Char literals/indexes
and int(char)/char(int) use checked 0..255 semantics. String equality is content,
struct/Vec/map equality identity; immutable tuple/enum equality is by value.

## Vectors

Vec header fixed payload: data reference at0. Backing object prefix: initialized
length at0, tail at8. Scalar int/bool/char tails use kind1; reference tails use
kind2. Capacity = (backing payload bytes - 8)/8. Bounds check every access.

```text
managedVecCreate(context, headerLayoutId, dataLayoutId, capacity): raw
managedVecLength(context, vector): int
managedVecCapacity(context, vector): int
managedVecGetI64(context, vector, index): int
managedVecGetReference(context, vector, index): raw
managedVecSetI64(context, vector, index, value): void
managedVecSetReference(context, vector, index, value): void
managedVecPushI64(context, vector, dataLayoutId, value): void
managedVecPushReference(context, vector, dataLayoutId, value): void
managedVecPopI64(context, vector): int
managedVecPopReference(context, vector): raw
managedVecTruncate(context, vector, length): void
```

Create/push may collect; other operations do not. Grow geometrically with checked
capacity arithmetic, allocate managed backing storage, copy initialized cells
with the right typed operation, and publish new backing before another GC.
No owned raw backing allocation/finalizer is required; dead old backing is
reclaimed by tracing. Reference writes reject region values entering heap data.
Empty pop and invalid get/set are runtime errors per SPEC. Bool encoding uses
explicit CFG conversion between IR bool and i64, never type-puns verifier types.

## Fixed immutable families

Extend lowering to tuples, nominal enums, Option<T>, Result<T,E> with exact
checked types, positional constructors, tuple numeric members, payload access,
isSome/isNone/isOk/isErr/unwrap/unwrapErr/unwrapOr, and ordered match statements.
Use immutable fixed objects: tuples have exact field descriptors; tagged values
have an outer tag:i64 + payload:reference object. Each payload shape has its own
descriptor so mixed scalar/reference alternatives never conservatively scan
integer payload words. Zero-payload variants use null payload. Sharing immutable
boxes is permitted only when observable value semantics are preserved; nested
struct/container references retain their shared identity. Matching must respect
bindings/scopes, first-arm order, checker coverage, recursive patterns, early
returns and source failures. Do not implement enums as struct identity equality.
The current experimental lowerer rejects structural equality whose immutable
type graph is recursive, using an exact type-identity path guard. Recursive
struct identity comparisons remain supported. Recursive immutable equality
needs generated recursive comparators before this restriction can be removed;
it must never expand the compiler indefinitely or fall back to identity.

The private outer reference field is named `$payload` with field.layoutId=-1,
allowed only in synthetic layout keys prefixed `$enum:`, `$option:` or `$result:`.
This sentinel means a canonical managed object whose runtime header selects its
exact descriptor. It is never a raw/interior address. Enum outer parameter/result
layout IDs stay positive. User fields cannot claim this sentinel; root validation
rejects other negative IDs/names/prefixes. Typed constructor/match lowering owns
the private payload shape proof. Runtime descriptors trace offsets and dispatch
through each child's actual layout ID; they do not guess one variant's layout.

## HashMap core

String keys only, matching SPEC. A fixed map object holds buckets reference at0,
len:i64 at8. Buckets use kind2 backing with initialized count equal to bucket
capacity and all slots typed null initially. Fixed node layouts hold key:string
at0, value at8 (i64/bool/char or reference), next:node at16. Exact reference
descriptors differ for scalar/reference value types. Hash all key bytes using
bounded checked arithmetic; use bucket chains and grow/rehash without losing
temporarily detached nodes at an allocation safepoint.

```text
managedMapCreate(context, mapLayoutId, bucketsLayoutId): raw
managedMapLength(context, map): int
managedMapHas(context, map, key): bool
managedMapGetI64(context, map, key): int
managedMapGetReference(context, map, key): raw
managedMapSetI64(context, map, nodeLayoutId, key, value): void
managedMapSetReference(context, map, nodeLayoutId, key, value): void
managedMapDelete(context, map, key): bool
```

Create/set may collect. Missing get is a runtime error. Dictionary literals and
HashMap.new use these APIs; reference values entering the heap cannot be region
objects. Preserve duplicate-key replacement, embedded-NUL keys, growth, deletion,
and aliases. Additional collection combinators/closure and I/O lowering remain
separate compiler sectors, not substitutes for memory correctness.

Checked expected types may specialize null literal leaves in aggregate shapes,
including `Vec<Node?>` and `HashMap<string, Node?>`. Concrete sibling types must
match and the expected nullable leaf must have a managed reference layout.
Locals, assignment, fields, calls and returns retain that exact shape. A null-only
aggregate without a concrete expected layout remains explicitly unsupported;
never infer a reference descriptor from an untyped null placeholder.

Write executable source/direct-runtime fixtures for all supported operations and
memory graph paths now. No executions before the coordinator's global barrier.
