# Rey v0.4 scalar IR core contract

This file defines the seed-compatible data model and deterministic printer in
`rey-compiler/src/ir/main.rey`. Implemented lowering, verification, evaluation
and native gates are recorded in [the parallel ledger](V0.4-PARALLEL-PHASES.md).
No managed collection or inferred-region implementation is claimed here.

## Scope and identity

The initial scalar type domain is `i64`, `bool`, and `void`. The `RawAddress`
extension below appends an internal type; ordinary scalar types remain
independent of
`typecheck.Type.kind` (which describes source-language types). `void` is a
function result / absent result marker, not a value that may appear as an SSA
operand or block parameter.

`SourceRef` stores `{unitId: string, start: int, end: int}`. Offsets are the
source unit's zero-based half-open offsets, copied from the checked frontend's
raw spans. The IR does not reinterpret them as line/column data or assume a
byte-versus-character unit different from the source lexer.
Each instruction and each terminator owns a `SourceRef`.

`FunctionKey` stores `{module: string, owner: string, name: string}`. `module`
is the checker's canonical module ID, `owner` is empty for a top-level
function and otherwise identifies its nominal owner, and `name` is the source
function name. `functionKeyName` prints `module::name` for an empty owner and
`module::owner::name` otherwise. These stable keys and IR function IDs are
separate from `ResolvedSymbol.llvmName`; no LLVM symbol is stored in this IR.
Checked AST/checker node IDs are not reused as function, block, or SSA IDs.
Source identity comes from `SourceRef.unitId` plus its checked source offsets.

Function IDs are nonnegative and unique across the entire `IRProgram`.
`nextFunctionId(program)` returns one above the largest existing ID (initially 0);
append functions with `withFunction`. A call's `functionId` refers to this
program-wide ID. Block IDs and SSA value IDs are nonnegative and unique within
one function. `nextBlockId(function)` returns one above the largest existing block
ID. Both helpers return -1 if the maximum signed-64 ID is already in use,
rather than overflowing; callers must reject exhausted ID spaces.
Function arguments and block parameters are typed `IRValue`s and take
values from the same per-function SSA ID space. ID `-1` is the sole absent
value/result sentinel: it is used for a void call result and a void return.
Other negative IDs are invalid.

Function parameter types in `FunctionSignature.parameterTypes` correspond by
position to `IRFunction.parameters`; block parameter types correspond by
position to the arguments passed on every incoming `Jump` or `Branch` edge.
The entry block has no incoming edge. A `Branch`'s condition is a bool SSA
value. `AddCheckedI64` and `CompareI64` take exactly two i64 operands;
comparison results are bool. Calls use ordered SSA operands and a target
function ID; the call's `ty` equals the target return type. A void call has
`resultId == -1` and type `void`. A `Return` has either a nonnegative value ID
or `-1` for a void result.

These shape and reference rules are preconditions for constructors and the
printer. They do not replace the separate verifier planned for M1. This core
does not perform dominance, target existence, arity, type agreement, ID
uniqueness, or source-span validation.

## Public data model

All fields are public, using seed-supported Rey structs and closed simple
enums so operation, terminator, type, comparison, effect, and escape tags do
not depend on payload-enum support.

```text
IRTypeKind = I64 | Bool | Void
InstructionKind = ConstI64 | ConstBool | AddCheckedI64 | CompareI64 | Call
  | SubCheckedI64 | MulCheckedI64 | DivCheckedI64 | RemCheckedI64 | CompareBool
TerminatorKind = Invalid | Jump | Branch | Return
CompareI64Predicate = Eq | Ne | Slt | Sle | Sgt | Sge
Fact = No | Yes | Unknown
Escape = NoEscape | MayEscape | Unknown

IRType { kind: IRTypeKind }
SourceRef { unitId: string, start: int, end: int }
FunctionKey { module: string, owner: string, name: string }
FunctionSignature { parameterTypes: Vec<IRType>, returnType: IRType }
IRValue { id: int, ty: IRType }
EffectSummary {
  readsMemory: Fact, writesMemory: Fact, allocates: Fact, mayBlock: Fact,
  synchronizes: Fact, unresolvedCallees: Fact,
  argumentEscapes: Vec<Escape>, resultEscape: Escape
}
Instruction {
  kind: InstructionKind, resultId: int, ty: IRType, operands: Vec<int>,
  immediate: int, comparison: CompareI64Predicate, functionId: int,
  source: SourceRef
}
Terminator {
  kind: TerminatorKind, targetBlockId: int, targetArgs: Vec<int>,
  conditionValueId: int, trueTargetBlockId: int, trueArgs: Vec<int>,
  falseTargetBlockId: int, falseArgs: Vec<int>, valueId: int,
  source: SourceRef
}
BasicBlock { id: int, params: Vec<IRValue>, instructions: Vec<Instruction>, terminator: Terminator }
IRFunction {
  id: int, key: FunctionKey, signature: FunctionSignature,
  parameters: Vec<IRValue>, blocks: Vec<BasicBlock>, effects: EffectSummary
}
IRProgram { entryFunctionId: int, functions: Vec<IRFunction> }
```

For `Instruction`, `operands` holds the two operands for checked addition and
comparison, and the ordered arguments for a call. `immediate` is the i64
literal or `0`/`1` boolean payload. `comparison` is meaningful only for
`CompareI64`; `functionId` is meaningful only for `Call`. For `Terminator`,
`Jump` uses `targetBlockId`/`targetArgs`; `Branch` uses the condition and both
successor/argument pairs; `Return` uses `valueId`. Unused fields are set to
`-1`, an empty vector, or the closed enum's first/default member by the
provided constructor.

The API treats `Vec` fields as immutable after a node is constructed. Build
local vectors with `push` or `set`, then pass them into constructors. The
`withInstruction`, `withBlock`, and `withFunction` helpers return a new outer
node with a copied-and-appended vector; nested nodes and vectors remain shared
and must stay frozen by convention.

Within this module, simple enums use qualified variants. External modules can
use the exported `compareEq`/`compareNe`/`compareSlt`/`compareSle`/`compareSgt`/
`compareSge`, `factNo`/`factYes`/`factUnknown`, and
`escapeNoEscape`/`escapeMayEscape`/`escapeUnknown` tag helpers. These helpers
also avoid requiring namespace-qualified enum syntax from older seed parsers.
`unknownEffects()` marks all effect facts and result escape unknown;
`noEffects()` returns a caller-asserted all-no summary. Neither function
infers or proves a summary. The convenience summaries start with an empty
`argumentEscapes` vector; callers must supply one element per formal argument
in signature order when constructing a function summary, using `Unknown`
where they cannot establish a safer fact.

## Deterministic printer

`printIR` emits functions and blocks in their vector order, and instructions
in block order. It does not sort or renumber IDs. Every printed operation and
terminator ends in its source reference `@unitId:start..end`. The format is:

```text
program entry=%f<entryFunctionId>
func %f<id> <qualified-key> (%v<id>:<type>, ...) -> <type> effects(read=<fact>, write=<fact>, alloc=<fact>, block=<fact>, sync=<fact>, unresolved=<fact>, args=[<escape>, ...], result=<escape>)
  bb<id>(%v<id>:<type>, ...):
    %v<id>:<type> = const.i64 <decimal> @<unitId>:<start>..<end>
    %v<id>:<type> = const.bool <true|false> @<unitId>:<start>..<end>
    %v<id>:<type> = add.checked.i64 %v<left>, %v<right> @<unitId>:<start>..<end>
    %v<id>:<type> = compare.i64 <eq|ne|slt|sle|sgt|sge> %v<left>, %v<right> @<unitId>:<start>..<end>
    [%v<id>:<type> = ]call %f<callee>(%v<arg>, ...) @<unitId>:<start>..<end>
    jump bb<target>(%v<arg>, ...) @<unitId>:<start>..<end>
    branch %v<condition>, bb<true>(%v<arg>, ...), bb<false>(%v<arg>, ...) @<unitId>:<start>..<end>
    return %v<id> @<unitId>:<start>..<end>
    return void @<unitId>:<start>..<end>
```

The bracketed call result is absent for a void call. The function header prints
formal SSA IDs and types from `IRFunction.parameters`; the signature's
parameter type vector gives the corresponding positional contract. Empty
parameter/argument lists print as `()`. The printer is for diagnostics and
fixtures; it is not a serialization format. Its precondition is a well-shaped
IR node, so malformed operand arrays are the verifier's responsibility.

## Effects and future memory model

`Fact` explicitly distinguishes `No`, `Yes`, and `Unknown` for memory reads,
memory writes, allocation, blocking, synchronization, and unresolved callees.
`Escape` distinguishes `NoEscape`, `MayEscape`, and `Unknown` per parameter and
for a result. Any analysis or optimization must treat `Unknown` conservatively
and may not silently convert it to `No`. These fields are summary storage
only; this slice contains no call-graph propagation, fixed-point analysis,
escape proof, allocation placement, or region reasoning.

Future IR extensions must add distinct types/categories for managed object
references, interior references/views, code pointers, raw owned buffers, and
integer payloads. They must carry nominal layout IDs separately from values,
and model `mayCollect`, roots, and safepoint operations explicitly before a
collector or backend may consume them. A raw owned buffer must not be mistaken
for a traced reference. This scalar core deliberately has none of those
pointer categories, layouts, GC roots, safepoints, or fake collection effects.

## Scalar arithmetic extension (next integration gate)

The coordinator added append-only instruction tags and constructors:
`subCheckedI64`, `mulCheckedI64`, `divCheckedI64`, and `remCheckedI64`, with
the same `(resultId, leftId, rightId, source)` signature as `addCheckedI64`.
All take two i64 operands and produce i64. `compareBool` has the same signature
as `compareI64`, takes two bool operands, produces bool, and permits only Eq/Ne.
The printer uses `sub.checked.i64`, `mul.checked.i64`, `div.checked.i64`,
`rem.checked.i64`, and `compare.bool`. Existing instruction tag order is retained.

Arithmetic traps on signed overflow; division and remainder trap on zero and
INT64_MIN with -1, matching the current reference engine. Division truncates
toward zero; remainder has the dividend sign. Evaluation must reject overflow
before executing an operation that could overflow in the seed host compiler.
Native errors use SPEC exit status 1. These tags are not accepted as complete
until verifier/evaluator/backend/source tests pass their next integration gate.

EffectSummary currently describes only its listed memory/synchronization and
escape properties. It is not a proof of absence of traps or divergence. No pass
may discard calls or checked arithmetic using these fields alone; trap and
termination facts must be established before such an optimization is enabled.

## Trusted raw-memory extension

`RawAddress` is a distinct internal value type, printed `raw.address`; it is
not an ordinary scalar or a managed reference. `irRawAddress()` constructs it.
The append-only instruction tags and their canonical constructors are defined
in [V0.4-RAW-MEMORY-CONTRACT.md](V0.4-RAW-MEMORY-CONTRACT.md). They reuse the
existing operand vector: no address is stored in an integer immediate and no
integer/address cast exists. Unused fields remain immediate 0, comparison Eq
and functionId -1. Stores and unmap have void type and resultId -1.

Raw values may flow through function parameters/results and parallel block
arguments in trusted code. A raw result is prohibited at the process entry.
Only source units explicitly authorized by the internal checker API can
introduce them; ordinary driver checks authorize no units. The evaluator's
bounded mapping model and native OS mappings are separate implementations of
these operations. Neither constitutes an automatic collector or region system.
