# Fixed-layout heap and collector bring-up, revision 1

Implementation target for the next runtime sector. This contract does not
establish an implemented collector. It extends the managed memory ABI with a
single-mutator, non-moving heap for fixed layouts only. The source interface
uses trusted raw addresses until managed-reference IR and compiler roots exist.
Application code receives no raw authority. Manual root tests alone do not
establish automatic memory management.

## Ownership and APIs

`runtime-rey/heap/main.rey` imports the fixed layout registry and owns object
storage. It never imports the collector. Its public trusted API is:

```text
heapCreate(registry: raw): raw
heapDestroy(heap: raw): void
heapRegistry(heap: raw): raw
heapAllocate(heap: raw, layoutId: int): raw
heapMark(heap: raw, object: raw): bool
heapSweep(heap: raw): int
heapLiveObjects(heap: raw): int
heapLivePayloadBytes(heap: raw): int
heapRequestedObjectBytes(heap: raw): int
heapRequestedMetadataBytes(heap: raw): int
heapCollectionCount(heap: raw): int
heapLastReclaimedObjects(heap: raw): int
```

Here `raw` means `__rey_raw_address`, not a new source type. A heap borrows its
live registry, which must outlive the heap and all collectors using it.
Allocation does not collect in this sector. It returns the canonical object
base with the ABI header, zero payload and explicitly typed null reference
slots. No variable arrays, container-owned buffers or tagged layouts are
supported. Reject invalid layout IDs through the registry API.

`heapMark` requires null or a live canonical object owned by that heap. Null
returns false. A previously unmarked object is marked and returns true;
an already marked object returns false. The caller establishes heap ownership
and provenance; a plausible header on an arbitrary address is not proof of it.
There are no integer casts, interior references or user-supplied raw values.
Marks must be introduced only during a complete collection before sweep.

`heapSweep` reclaims all unmarked allocations, clears marks on survivors,
updates counters, and returns the number reclaimed. It completes one
collection, incrementing the collection counter even when nothing is reclaimed.
Destroy consumes the heap and releases every owned mapping regardless of marks.
Destroying a registry first, using a freed object, and releasing twice are
trusted caller errors. No finalizers, weak references or concurrent mutators.

## Object and slab storage

Object bases and allocation sizes are 16-byte aligned. Header word at offset 0
is `layoutId + mark * 4294967296`, where mark is 0 or 1; all other flag bits are
zero. Offset 8 holds the exact nonnegative payload byte count. Payload begins
at offset 16. Arithmetic is checked before allocation or mutation.

Small allocations use classes 16, 32, 64, 128, 256, 512, 1024, 2048, 4096,
8192 and 16384, selecting the smallest class fitting header plus payload.
Each slab is one exact requested 65536-byte mapping. Its first 4096 bytes are
metadata; object slot `i` begins at `4096 + i * classSize`, with
`slotCount = 61440 / classSize`. All slots are canonical object bases.

Each block has the following metadata; words not specified are zero:

| Offset | Field |
| --- | --- |
| 0 | typed raw next-block address |
| 8 | free-list slot index, or -1 |
| 16 | live allocation count |
| 24 | class/slot byte size |
| 32 | original requested mapping length |
| 40 | slot count |
| 48 | class index 0..10; -1 for a large block |
| 56 | magic 1380272203 |
| 64 | next never-allocated slot index |
| 128 + i | allocation flag byte, 0 or 1 |

Never-allocated slots need no eager free-list construction. Allocation first
uses the free list, otherwise consumes `nextUnused`. A freed slot stores its
next free index as an i64 in its first word. Only flag-1 slots are scanned.
Before a reused slot is published, reinitialize its header and entire actual
payload, then store typed nulls at every descriptor reference offset. Byte or
integer zero stores alone do not restore evaluator address-cell provenance.

Allocation validates context/block bounds and the selected free slot/link,
including a self-link, before publishing that slot. It does not traverse every
flag or the entire free list on each allocation. Sweep audits all blocks before
reclaiming; destroy audits each block before releasing it. These audits check
flags, per-block counts, free lists and reserved bytes. Arbitrary trusted
metadata corruption can therefore be detected only when its relevant path is
examined; this API is not an untrusted-memory sandbox. This distinction avoids
an allocation cost proportional to all slots in the slab.

Objects exceeding the largest class use one dedicated block with one slot at
offset 4096. Its exact requested mapping length is
`4096 + align16(16 + payloadBytes)`. Its slot size is the aligned object size,
class index -1, slot count 1. It participates in a separate block list.

Sweep trims **every empty block** initially. For retained blocks, rebuild free
lists from allocated flags while preserving the next-unused boundary. Reclaim
an object once, preserve live object addresses and shared identity, and unmap
blocks using their original requested lengths. No raw byte-buffer copying of
pointer-bearing metadata is allowed.

## Heap context and accounting

The heap context is one exact requested 256-byte mapping:

| Offset | Field |
| --- | --- |
| 0 | magic 1380272200 |
| 8 | typed borrowed registry address |
| 16 | live object count |
| 24 | live payload bytes |
| 32 | requested bytes in owned object block mappings |
| 40 | typed large-block head |
| 48 | completed collection count |
| 56 | most recent reclaimed object count |
| 128 + classIndex * 8 | typed small-class block head |

`heapRequestedMetadataBytes` reports 256 while the heap lives. Object mapping
bytes include slab/block metadata, headers and unused slots. Registry storage
is borrowed and excluded. These are **requested mapping lengths**, not OS page
reservation or resident memory. Do not label them RSS or use them to claim a
process memory plateau. Expose counters through the APIs, never read released
contexts for statistics.

Use RawFail 2001 for invalid/overflowing sizes, 2002 for corrupt heap/block or
object metadata detected by the trusted API. Registry validation retains its
1001..1006 codes. Native mapping failure retains the primitive's status 1.
Validate before mutation; an error ends the process, so no recovery is promised.

## Collector and explicit roots

`runtime-rey/gc/main.rey` imports heap and layout. Its trusted API is:

```text
gcCreate(heap: raw, initialRootCapacity: int): raw
gcDestroy(collector: raw): void
gcRootPush(collector: raw, object: raw): int
gcRootSet(collector: raw, index: int, object: raw): void
gcRootPop(collector: raw, index: int): void
gcRootCount(collector: raw): int
gcRequestedMetadataBytes(collector: raw): int
gcCollect(collector: raw): int
gcAllocate(collector: raw, layoutId: int, collectBefore: bool): raw
```

The collector borrows one live heap. Destroy it before destroying the heap.
Roots are canonical live objects in that heap, or null. Push returns a stable
index while that root remains on the stack; pop requires the current last
index, clears its typed address slot and consumes it. Set requires an existing
index. Callers publish construction temporaries before another collecting call.
`gcAllocate(..., true)` collects **before** allocating, never after allocation;
the returned object must be published before the next collecting operation.
This stress mode tests runtime discipline, not compiler-generated roots.

The collector context is 64 requested bytes: magic 1380272201 at 0, typed heap
at 8, typed root-array address at 16, root count at 24, root capacity at 32,
reserved 40..63 zero. Root storage is capacity * 8 requested bytes, null when
capacity is zero. Grow to at least 8 and then double with checked arithmetic.
Initialize typed slots and copy roots with typed address loads/stores. Publish
new storage before unmapping the old array. Metadata accounting is 64 plus
the current root-array requested length; collector work storage is temporary.

Collect uses an iterative typed-address worklist with capacity equal to the
heap's live object count at entry. Mark **before enqueue**, so aliases/cycles
enqueue each object at most once. Visit explicit roots, then use each object's
layout ID and descriptor offsets to load only typed reference fields. Never
scan pointer-shaped integer payloads or recurse through user graph depth.
Worklist maps never collect recursively. Sweep after marking completes, then
unmap work storage at its original length. Empty heaps require no work mapping.
Use RawFail 2101 for invalid sizes, 2102 corrupt collector metadata, 2103 invalid
root index/order and 2104 violated worklist bounds/invariants.

## Gates before acceptance

Write all code and fixtures before testing. Use the actual trusted source
through checking/lowering/verifying/evaluation and direct native emission.
Run source cases in separate seed-built harness processes. Execute both Darwin
and Linux ARM64 images; preserve snapshots, exact statuses and failure spans.

Allocator tests cover class boundaries, 16-byte layout, zeroed fields and
typed references, multiple blocks, large objects, address stability, free-slot
reuse, trimming, exact counters, invalid sizes/metadata and teardown. Collector
tests cover aliases, self/two-object cycles, deep graphs, nulls, pointer-shaped
integers, rooted/unrooted objects, root growth/set/LIFO errors, and collection
before every allocation with construction roots. Check live/copy/mapping
counters explicitly. Repeated bounded-live tests must exceed 256 total maps
over time without exceeding evaluator live-map limits. Record evaluator limits
separately from native results. Compiler roots, source aggregates, owned-buffer
tracing and all-platform release gates remain subsequent work.

The historical seed's evaluator exhausted 20 million steps and reached a
9.05-GB peak footprint while simulating 128 collections during graph creation.
Separate coverage: interpret a 128-node graph with collection after construction,
interpret a smaller graph forcing collection before each allocation, and emit
the full 128-allocation forced-collection graph for actual native execution.
Only `fixed-gc/native-collection-stress-128` may skip bounded interpretation;
its explicit `.evaluation` record says `native-only`, its step count is zero,
and both native programs must execute their full assertions. Preserve the
exhausted evaluator evidence. This does not waive native forced-collection,
source checking/lowering/verification, root or descriptor correctness gates.
