# v0.4 release readiness

v0.4 is not released. This note lists the gates that must pass before a
platform or a performance sentence can be published. Aspirational targets in
the execution plan are not observations.

## Package contract

The compiler/runtime package contract is `rey-package-1`, described in
`packaging/README.md`. Capy `0.1.1` still pins Rey `0.3.1` and the legacy
`librey_rt.a` layout. `reyPackageVersion()` returns `0.4.0` as the contract
version, not as the version of an installed compiler. Doctor accepts `0.4.0`
only when the toolchain's `package.toml` says `rey-package-1`.

Clang and Xcode command-line tools remain required for a legacy toolchain.
They are not required for `rey-package-1`. macOS still loads through dyld and
libSystem. Linux scalar programs use a direct exit syscall. Windows scalar
programs import `ExitProcess` from `kernel32.dll`. None of those loader facts
is a package-install result.

`packaging/update-manifest.toml` and Capy's
`packaging/update-manifest-v04.toml` keep every platform `blocked` and leave
download URLs empty. The existing four-host `latest.toml` generator is
unchanged. Homebrew and npm do not gain a Windows package from this change.
The existing `@capybara/darwin-x64` package is the legacy Capy host package.
It is not evidence that the new x64 backend runs on Intel macOS.

## Five platforms

| Platform | What this change can generate | Execution evidence required before a release claim |
| --- | --- | --- |
| `darwin-arm64` | unchanged existing backend | a current native hardware run of the release package |
| `darwin-x86_64` | Mach-O x64 cross output | a native Intel macOS run; the declared 11.0 version is not that run |
| `linux-aarch64` | unchanged existing backend | a current native or VM run of the release package, named as such |
| `linux-x86_64` | existing ELF executable plus a relocatable object | native x64 hardware; VM emulation is not that gate |
| `windows-x86_64` | PE32+ cross output | a native Windows run of the produced image |

`scripts/v04-release-readiness.py` reads one JSON file per platform. A
platform is accepted only when `build`, `run`, `bootstrap`, and `package` are
all `pass`, `nativeHardware` is true, and `emulator` is false. `built`,
`structural`, and `executed` are observations. A Rosetta run, a Linux VM run,
or a structural PE check can set `executed` without setting the release `run`
gate. Missing files fail the gate. The script does not build or execute
anything, and it does not write a download URL.

## Performance

No speedup is claimed. Clean-build and one-function-edit targets in the
execution plan stay targets. Capy prints `observation: not measured` unless a
record carries at least nine samples, and even then the line is an
observation, not a pass against the 100 ms or 50 ms targets. There is no
claim of being faster than C, C++, Rust, Zig, Go, or Python.

## Provenance still required

A releasable note has to name the compiler and runtime source revisions, the
seed hashes, the native bootstrap command and its artifact hash, the five
evidence files above, semantic changes since 0.3.1, raw benchmark samples, and
the limitations in this file. This change does not supply those hashes or
samples.

## Limitations

- The incremental cache is still a library. `rey-compiler/ir-main.rey` `emit`
  calls `emitImage` for every x64 target. `rey-compiler/native-main.rey` calls
  `emitImage` for `darwin-x64` and `windows-x64`. Its `linux-x64` branch calls
  `emitProgram`, which returns the code from the same image emitter.
  Neither driver writes the cache report.
- Capy's no-op decision is a file-hash decision. It is not the compiler's
  effect invalidation. One-function text classification always reinvokes the
  compiler.
- x64 emission is the existing scalar subset. Raw memory, regions, and managed
  aggregates are not lowered by this backend.
- Windows `.pdata` on the driver-built `native-add-windows-x64` image covers the entry stub (`0x1000–0x1011`) with `UWOP_ALLOC_SMALL` for a 40-byte allocation. Wine 6.0.3 in the amd64 container returned exit 0 for the driver images and exit 42 for the IR fixture. A Windows machine run is still required before a release claim.
- Darwin x64 exits with a direct syscall inside an image that also requests
  libSystem. That image ran under Rosetta 2 on this Apple Silicon Mac (exit 0
  for the driver programs, exit 42 for the IR fixture). An Intel Mac run is
  still required before a release claim.
- Production memory remains the region model. This work does not add a
  collector, a safepoint, or reference counting.
