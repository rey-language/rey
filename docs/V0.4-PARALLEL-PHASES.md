# v0.4 parallel implementation ledger

User operating choice: three highly scoped GPT-6 Luna workers at medium effort plus the coordinator. Workers write their whole assigned implementation and fixtures before running tests. After tests and coordinator integration pass, advance automatically. The coordinator alone owns Git, shared contracts, integration entrypoints, and project handoffs.

The approved architecture remains [V0.4-EXECUTION-PLAN.md](V0.4-EXECUTION-PLAN.md). The new runtime consumes [V0.4-MEMORY-ABI.md](V0.4-MEMORY-ABI.md). Performance targets are not observed results.

## Phase order

1. **Readiness/contracts:** seed probes and baseline gates; matched benchmark tooling; scalar IR core/contract. Coordinator freezes memory/native interfaces and reviews actual evidence.
2. **Typed IR:** checked-source lowerer; independent verifier; evaluator/effect summaries. Coordinator connects an experimental driver and runs differential checks.
3. **First native executable:** ARM64 backend; byte/image writer/linker; minimal Rey runtime/OS interface. Coordinator requires actual execution without a compiler-tool subprocess or linked Rey C runtime.
4. **Runtime/self-host:** native feature/root coverage; tracing collector/buffers; string/container/value runtime. Coordinator validates forced collection and the H/S1/S2/S3 bootstrap.
5. **Memory optimization:** escape/effect facts; scalar/stack transformations; regions/destination construction. Integrate in that order and keep independent off switches. Uncertain promotion uses safe storage, not unchecked copying.
6. **Structured parallelism:** syntax/isolation checks; task scheduling/helping joins; mutator roots/collector coordination. Include tasks in v0.4 before release, using the restricted memory ABI surface.
7. **Performance/incrementality:** streaming fusion; machine-code optimization; compiler cache/Capy. Measure real process, compilation, copying, and memory costs separately.
8. **Platform completion:** x86-64/ABIs; ELF/Linux; PE/Windows. Require native results on all five supported platforms, including macOS Intel.
9. **Release review:** independent semantics/backend review; memory/concurrency review; packages/installers/migration. Parent resolves findings and assembles evidence before any release claim.

## Ownership and gates

- Current shared workspace has exclusive file scopes. Workers do not change shared interfaces or another sector's files. Interface requests go to the coordinator.
- Use distinct `build/v04/<sector>/` output paths. Full compiler bootstraps, large checks, and benchmark runs are serialized on the development host. Lightweight sector checks can run concurrently.
- Hand back changed paths, exact test commands/statuses, known failures, and public API details. Stop edits at handoff until the next assignment.
- The coordinator inspects every diff and runs integration checks before accepting results. Commit only selected reviewed paths after writers have stopped. Never overwrite a peer's changes or run broad cleanup.
- Source can retain the seed's supported syntax while the new compiler recognizes runtime intrinsics as input. Historical C/LLVM dependencies remain seed-only; production native code never silently falls back.

## Initial dispatch

- Seed worker owns `scripts/v04-seed-probe.py`, `scripts/v04-baseline.py`, and seed fixtures under `tests/v04/seed/`.
- Benchmark worker owns `benchmarks/v04/`, initially a matched numeric loop and repeated-vector churn for C/C++/Rust/Zig/Go/Python/Rey.
- IR core worker owns `rey-compiler/src/ir/main.rey`, its contract, and core fixtures. Lowering, verification, and evaluation are separate subsequent assignments.
- Coordinator owns this ledger, shared memory ABI, baseline integration, compiler entrypoints, and contributor docs.

## Compiler-managed roots, aggregates and regions — 2026-10-21

Three scoped GPT-6 Luna medium workers wrote the aggregate lowerer, managed
runtime/containers, and root/placement/checker sectors in parallel. The
coordinator opened the global execution barrier only after all implementation
and fixtures were written. The following integration phase repaired observed
defects rather than treating code delivery as acceptance.

The new pipeline retains checked source identities in exact fixed and variable
layouts, then inserts precise shadow roots before collecting calls. Typed
payload descriptors cover structs, tuples, nominal enums, Option/Result,
strings, vector backing stores and string-key maps. Derived addresses cannot
cross safepoints. Runtime linking validates exact module identities, signatures
and transitive collecting behavior before replacing private lowering hooks.
Ordinary source compilation receives no raw-memory authority.

Fixed allocations with proven lifetimes use pooled bump regions; returned
objects can be constructed in caller destinations. Stores enforce lifetime
direction, and region reference cells trace heap children. CFG-cycle allocations,
dynamic backing storage, and uncertain reference-field ownership fall back to
the precise nonmoving heap. Destination construction preserves aliases; moving
an already aliased graph is not implemented.

Integration found missing String tail descriptors, lost tagged-constructor
arguments, a Result payload-layout omission, a vector argument-index error,
mutable-match SSA joins, and a derived-pointer adjacency validation error.
Placement fixes propagate return aliases and conservatively retain loaded
reference graphs on the heap. Recursive immutable value equality now fails with
a typed diagnostic instead of recursively expanding the compiler.

Final runtime review also found two malformed reference-tail descriptors that
registration accepted: a fixed reference overlapping the initialized count, and
an unaligned prefix. Both registration and later descriptor validation now
reject them. Five new fixtures cover both rejection paths, descriptor corruption,
and a valid mixed prefix whose fixed and tail references retain heap children.
Those repairs were frozen before the subsequent test wave.

Checked nullable aggregate contexts specialize null literal leaves only when
concrete siblings match the expected shape and the nullable leaf has a managed
reference layout. Uncontextualized null-only storage remains unsupported rather
than receiving a guessed tracing descriptor. Supplemental generic-storage tests
cover nullable literals and mutations, reference identity, boolean pop/set, and
the full byte range for characters.

Shadow root cells are colored by canonical references published together at
safepoints. Each cell is cleared once before live values are published, so a
dead alias cannot clear a live value sharing the cell. Bounded planning falls
back to one cell per canonical reference. The container fixture's `main` uses
four cells versus 46 before this change; its optimized native build executes.
This is a root-count observation, not a measured speedup.

The larger runtime exposed repeated live-set clique construction and liveness
rescans. Slot interference now uses verified SSA definition/live-after and
parameter edges; independent fixtures still check every simultaneous-live pair.
Liveness precomputes block use/definition transfers and merges operand sets once.
Both analyses retain a one-million-unit limit per independent function, with
contextual exhaustion diagnostics. Total allowed work scales with function
count. A 500-function composition fixture passes; the old shared-budget control
rejects that exact fixture. A separate 600-live-value function still rejects at
the individual bound. No partial analysis or unsafe layout is returned.
