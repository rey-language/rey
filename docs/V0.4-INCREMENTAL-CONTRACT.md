# v0.4 incremental cache and platform image contract

This contract covers the compiler cache, the Capy no-op and explain surface, and
the x64 image writers added beside the existing Linux ELF executable. It does
not change the production memory path. Production managed memory stays
region-only: no tracing collector, no GC roots or safepoints, and no reference
counting. Historical fixed-heap and collector code is not part of this cache or
these image writers.

No timing number in this document is a measurement.

## Cache identity

`rey-compiler/src/ir/cache/main.rey` publishes `requestKey`. The key is the
SHA-256 of the canonical request. The request includes the artifact kind, unit
id, source digest, transitive dependency digest, compiler ABI
(`rey-ir-cache-1`), runtime ABI (`rey-region-v0.4`), target, semantic flags,
optimization settings, and the effect, layout, inline, and specialization
digests, plus the sorted cache keys of dependency artifacts.

A source-text digest alone is not a key. An empty digest is a real value, not
a wildcard. Callers that do not yet know an effect, layout, inline body, or
specialization pass the digest of an explicit `unknown` text. They must not
omit the field to force a hit.

`planRebuild` compares unit snapshots:

- A changed function body rebuilds that unit. Callers are not rebuilt when the
  effect, layout, inline, and specialization digests are unchanged.
- A change to any of those four digests rebuilds the unit and every current
  unit that reaches it through `dependencyUnitIds`. The walk is bounded by the
  square of the unit count; if the bound is hit, every current unit is
  invalidated.
- A target, ABI, flag, or optimization change, or an added or removed unit or
  function, is a full rebuild.
- `relink` is true whenever any unit is rebuilt. An unchanged caller still
  needs a new link when a callee object changed.

## Persistence

Records use format `rey-cache 1`. `commit` writes a build-private partial file,
reads it back, and only then moves it into `objects/<key-prefix>/<key>.record`.
`lookup` returns a payload only when the header, the recomputed key, the
payload length, and the payload digest all match. A mismatch, a truncated
file, or a payload collision quarantines the record and returns no payload.
Cache failure is a miss or an error. It is never a successful stale hit.

`prune` removes the oldest unprotected records until the store is within
`maxBytes`. Records written by the current `commit` are protected for that
call. If protected records alone exceed the budget, `commit` discards the new
record and returns an error. Two builds isolate partial files by `buildId`.
The cache root must stay on one filesystem so the final move does not copy a
partial file into place. This module does not take an exclusive lock against
another build publishing the same key.

## Resource contracts and explain labels

`checkNoHeap` and `checkNoBlocking` walk the root and the supplied callee rows.
A trusted `no` for every row is `established`. A trusted `yes` is an
established violation and includes `path`. Anything untrusted, empty, or
unrecognized is `unknown` and is not success. Foreign functions without a
trusted summary stay unknown.

Explanation lines use exactly one of these prefixes: `established:`,
`estimate:`, `observation:`, `unavailable:`. Capy uses the same prefixes.
`observation: not measured` is the required text when no accepted sample file
exists. A measured line is an observation only when a record contains both
`measured-ms` and `measured-samples` and the sample count is at least 9. That
line is not a statement that a performance target was met.

## Capy

`capy build` hashes the entry, project `.rey` files, `capy.toml`, and the
toolchain standard library. A no-op skips the compiler only when that identity
is contained in a valid `capy-incremental 1` record and the output file's
SHA-256 matches `output-digest`. A one-function classification is a text
estimate of the entry file. Capy still runs the compiler for that class. It
does not claim the compiler reused an object. `--no-incremental` forces a
compiler run. If `shasum` and `sha256sum` are both unavailable, Capy runs the
compiler.

`capy explain` prints the record it found and ignores lines that do not use
the four prefixes. Without `rey-cache-report.txt` next to the record, the
compiler cache is `unavailable`. The experimental drivers are not wired to
write that report; wiring them is coordinator work.

## x64 images

`emitProgram` and `emitProgramWithReuse` still accept only `linux-x64` and
return `X64Code`. `emitImage` and `emitImageWithReuse` also accept
`windows-x64` and `darwin-x64`. `macos-x64` is a name for `darwin-x64`.

Linux and Darwin use the SysV registers `rdi, rsi, rdx, rcx, r8, r9`. The
frame pointer is `rbp`. The emitter does not use the SysV red zone. Linux exit
and overflow use syscall 60. Darwin exit and overflow use syscall
`0x2000001`. The Darwin Mach-O still requests `/usr/lib/dyld` and
`/usr/lib/libSystem.B.dylib`, and its build version field declares macOS 11.0.
That declaration is not a test on Intel hardware. The direct syscall may be
rejected by the platform.

Windows uses `rcx, rdx, r8, r9`, 32 bytes of shadow space, and incoming stack
arguments at `rbp+48`. Exit and checked overflow call `ExitProcess` through a
RIP-relative relocation (`kind` 1) to the `kernel32.dll` import address table.
`buildPeX64` writes a PE32+ image with `.text`, `.idata`, and `.pdata`.
`.pdata` covers generated functions that use the standard frame-pointer
prologue. The entry stub is not in `.pdata`.

`buildElfX64` is unchanged and remains the Linux executable writer.
`buildElfObjectX64` writes a relocatable ELF64 object. `R_X86_64_PC32` is used
for kind-1 relocations with addend -4. An object file is not an executable.

These writers do not call an assembler, linker, or C compiler. They also do
not prove that the image runs. Linux x64 execution evidence that already
exists is emulation in an ARM64 Linux VM, not native x64 hardware. Windows and
macOS x64 have no execution evidence in this change.

The scalar emitter still rejects raw-memory and managed instructions. Region
lowering is not emitted here.

## Platform facts

`runtime-rey/platform/main.rey` records the same Linux, Windows, and Darwin
x64 numbers as the comments in `rey-compiler/src/native/x64/main.rey`.
`generatorUsesRedZone` is false. `executionEvidence` is a label, not a new
test result. ARM64 rows describe the existing backends; this sector does not
edit them.
